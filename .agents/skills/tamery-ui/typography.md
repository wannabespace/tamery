# Typography, density & radius

- Fonts: Geist / Geist Mono (fontsource variable, globals.css), upright and `wght-italic` both imported — without the italic file `italic` renders a faked slant. Monaco's `fontFamily` must name the same family as `--font-mono`.
- `text-sm` primary labels (rows, tabs, popup rows) · `text-xs` secondary/chips/menu group labels · `text-2xs` micro labels; section headers add `font-semibold tracking-wider uppercase text-muted-foreground`.
- Row heights: menu/list rows `h-7`, connection-list rows `h-9`, tab bar and pane headers `h-8`, toolbars `h-11`–`h-12`, chips `h-5`–`h-6` (`Badge size="sm"` is the `h-4`/`text-2xs` tier, for chips packed many-to-a-cell; `Kbd` drops to it inside tooltips). The data-table header has **no fixed height** — padding and line heights land on the right pixel naturally; `--table-header-height` must match it, and its hairlines stay non-layout (`inset-ring`).
- **Kit `Table` has two tiers**: default (`text-sm` rows, `h-8` `th` at `text-xs text-muted-foreground`, `p-2` cells) — a macOS list header, not the registry's — and `size="sm"` (`text-xs` throughout, `h-7` `th`, `h-8 px-3` cells, zebra rows without borders), the data grid's density, for tables inside popovers and inspectors. A page that wants other rows says so in the kit, never by re-dialing `td`/`th` padding, height or font size at a call site. Header rows never hover, so no call site turns it off.
- `tabular-nums` for counts in lists and columns, where digits must align — not for a lone count in the floating grid bar (`Delete (12)`, summary stats), which reads as label text. `font-mono` for hosts, SQL and code only — object names and enum values are read as plain text, since mono is for code, not for identifiers in a table. A one-line SQL preview in a popover list (run history, saved queries) is a row label and stays sans; mono is for SQL shown as code.
- **Three weights, by role.**
  - Body `400` for controls — `Button`, `Toggle`, `ButtonGroup`, `InputGroupAddon` carry no `font-medium`, so a control label never outshouts the values around it. A call site adding `font-medium` to a button is re-dialing the kit.
  - `font-row` (450) is the **floating-row** weight, a half-step the variable face gives for free: menu, command and context-menu items and tab-bar tabs, so rows on a popup surface read a touch firmer than prose. `SelectItem` is the exception — its popup overlays the trigger, so its rows keep the trigger's weight and tracking or the value reflows on open. `Command variant="flat"` is a page-surface list, so its items stay at body weight.
  - Rows on a page surface (navigator, definitions, action rows) stay at body weight; a selected sidebar menu row steps up to 550 over the hover fill ([colors.md](colors.md)).
  - `font-medium` is for type roles, not chrome — titles and headings, labels and field legends, `TableHead`, and chips that have to read at `text-xs` (`Badge`, `Kbd`, combobox chips).
- **Radius scales with size and the kit encodes it — don't override.** `h-8`+ controls `rounded-xl`, `h-7` `rounded-lg`, chips/badges/kbd/checkboxes and menu items `rounded-md`–`rounded-lg`. `Button`, `Select`, `InputGroup` and `Toggle` take `size` (`sm` = h-7, `xs` = h-6), which sets height *and* radius — a hand-set `h-7` leaves the radius wrong. Multi-line fields sit on the `h-8` tier. Floating containers are `rounded-xl`, except a `Select` popup, which opens over its trigger and so takes the trigger's radius — pass the trigger's `size` to `SelectContent` too; `rounded-3xl` only for the command palette and chat bubbles. Nested pills follow the concentric rule (inner ≈ outer − padding).
- **A control placed under or beside a surface takes that surface's tier**, with no exceptions — including one that only adds to the surface above it ([patterns.md](patterns.md), editable value lists). `Skeleton` defaults to `rounded-md`: it stands in for text lines far more often than for a control.
