# Motion

## Principles

A new animation answers to these before it picks a curve. This is a windowed desktop app driven by a pointer and the keyboard — there are no swipes to ride, so the principles land on drags, folds, swaps and key repeats.

- **Every animation is interruptible, because the input that interrupts it is the normal one.** Panes get toggled faster than they fold, tabs switch mid-cross-fade, a drawer is reopened while it is still leaving. The replacement inherits the velocity of what it cut off (motion, never CSS transitions), and no state may be correct only once an animation has finished — an animation is how a change looks, never when it takes effect.
- **A drag moves its surface from the first pixel.** Pane separators, column resize, the `EditableList` grip, reorderable strips, swipe-dismiss: each follows the pointer directly, animates nothing while the pointer is down, and stops any fold it interrupts. A threshold decides the *outcome*, never whether the surface has started answering.
- **Where a change commits is a function of what it costs.** Reversible, purely visual outcomes resolve live, so backing out is dragging back (a pane collapses as the pointer crosses the threshold and reopens if it crosses back; Escape restores the size the drag started from). Anything that persists or runs commits once on release, never per frame.
- **Motion states where a surface lives.** A surface enters from its own edge and leaves the same way — drawers from the right, a pane out of its seam, a popup from its anchor. A fade in place gives the user a surface with no address; an arrival from somewhere it does not live sends them looking in the wrong place next time. That is why a list collapsing is its rows sliding to their new `y`, not rows fading where they stand.
- **Frequency is the animation budget, and the keyboard sets the ceiling.** Anything a held key repeats gets no animation at all; anything opened dozens of times an hour stays at popup weight (150 in, 100 out); a longer curve is affordable only where the moment is rare and page-sized. A flourish met twenty times an hour is friction, and on a list it is smear.

## Recipes

- `motion` library for interruptible animation, not CSS transitions (transitions snap under frame drops). Exception: pure colour/opacity hovers.
- House curve `[0.32, 0.72, 0, 1]`, 150–300ms; in classes it is the `ease-house` theme token, never a hand-written `cubic-bezier`. Collapse via width/transform; no whole-panel opacity fades. `AnimatePresence` for mount/exit of conditional chrome. No layout shifts on hover — reserve space, animate opacity/transform only.
- **A `transition-[…]` list must name every property the element's own state variants change.** A surface hovering both its ring and its fill but listing only `box-shadow` reads as two durations on one control. Rings and shadows are `box-shadow`; `transition-colors` never covers them. Siblings lighting up on the same pointer event share one duration.
- **Ghost buttons hover instantly.** Toolbar and breadcrumb triggers sit in rows the pointer sweeps across; a fading fill trails behind the cursor. The ghost variant transitions `transform` only (press nudge).
- **Anything keyed to the highlighted row of a keyboard list has no transition** — the highlight jumps a row per keystroke and a fade smears indicators down the list. Hover-only reveals inside one row may still fade.
- **Definition rows do not animate at all.** Schema picks, searches and filters replace the whole row set, so per-row enter/exit leaves old rows holding their place while new ones mount below — the table doubles its height and snaps back. Row-level `AnimatePresence` is for rows arriving in a list that stays the same list; the only animation there is the skeleton→content swap around it, whose exit runs at `duration: 0` so `mode="wait"` does not hold an empty pane.
- **Virtualized reorder** (navigator tables): motion `layout` cannot work with tanstack-virtual — stable `getItemKey` + `motion.li` `initial={false} animate={{ y: virtualRow.start }}`. Rows sliding to a new `y` *is* the collapse animation; `{ duration: 0 }` while search filters, since churn per keystroke reads as noise.
- **Swapping two panels in one slot**: `AnimatePresence mode="popLayout"`, opacity + small `x` offset in the push direction, 150–180ms.
- **Dock items fold sideways; separators are keyed by the item after them.** Each `GridBar` item and its leading separator animate `width` 0 ↔ auto + opacity (150 in, 100 out), so the bar resizes around its centre; the separator's key follows the next item, so when the first item leaves, the new first item's separator folds out with it instead of popping. Items clip with `overflow-clip-margin` equal to the bar padding so focus rings and badges survive. The bar itself rises 8px from the edge it lives on.
- **Collapse/disclosure**: animate CSS grid rows (`gridTemplateRows` `0fr` ↔ `1fr`) around a `min-h-0 overflow-hidden` child.
- **Rotating or swapping one line of text** (an idle → filled title): `AnimatePresence mode="popLayout" initial={false}` with the line keyed by its text, entering from `y: 100%` and leaving to `-100%` on the house curve (250ms), inside a `relative overflow-hidden` wrapper; without it the popped exiting line floats over the row above. Rotation stops under reduced motion and once the line has something real to say.
- **A refused action shakes its control**: `useAnimate` on a wrapping `motion.div`, `x: [0, -6, 6, -3, 0]` over 300ms, skipped under reduced motion, with the reason swapped into the control's own text, never a toast for a miss the user can retry in place.
- **A page form rises in on mount**: its blocks on a `staggerChildren` parent (0.04s), each block `opacity` + `y: 8` over 250ms.
- **Never animate `filter` (blur) and never loop an animation on a blurred layer.** Blur is repainted per frame across the element's whole area, so blurring cards, a full-page surface or a blurred shape in or out lags the click that started it, worst on Retina. Entrances are opacity + transform only.
- **A conditionally rendered note animates in and out** — `AnimatePresence initial={false}` around `MotionCollapse` (`collapse.motion.tsx`), keyed per condition so two exclusive notes cross over instead of jumping. An alert popping into a form the user is filling reads as a layout glitch. **The stack's gap animates with it**: a collapsed item is still a flex item, so `MotionCollapse` folds the parent's `rowGap` into its own clipped height — grid parents (the kit's dialogs) ignore item margins and keep the snap. **It clips with a `clip-path` inset 4px past its box, never `overflow-hidden`**, which cuts the focus and invalid rings of the controls inside it.
- **Popup enter/exit** (all kit menu/popover/select content): `animate-in/out` + fade/zoom/slide, `data-open:duration-150 data-closed:duration-100` on the house curve — the shipped defaults read as no animation. Exits stay shorter than entries. The grid's cell editor is the exception: it opens on a keystroke, so it appears and leaves with no animation.
- **One popover shared by a row of triggers** (runner result tabs): a base-ui handle (`createPopoverHandle`) with the source as trigger `payload`, and `PopoverContent detached` — the popup glides between triggers, resizes, and cross-fades its content in the activation direction. Never one popover per trigger: hovering along the strip then flickers closed and open.
- **Tab content swap** cross-fades in `$tabId.tsx` with `AnimateView` (`motion/react-animate-view`, a React `<ViewTransition>`): the outgoing tab is a browser snapshot, so only one tab is ever mounted and tab hotkeys need no conflict handling. Router state reaches React through `useSyncExternalStore`, whose commits are always sync and never start a view transition, so the tab renders from `useDeferredValue` of the route's tab and resource id — the deferred re-render is what animates. Keyed on resource id + `tab.id` — a tab id repeats across resources, so keying on it alone keeps one resource's state and placeholder rows alive under the next. Page-level swaps only: a view transition cannot be interrupted and blocks pointer input while it runs, so in-page chrome stays on `AnimatePresence`. The tab strip's active fill, text and icon color transition at the same duration, so the tab and its page change together.
- **The grid cursor scrolls with a glide; the cursor itself jumps.** Arrow keys move the cell outline instantly, and the scroller follows in 120ms on the house curve — the one held-key exception, because each repeat stops the running glide and starts from where it stopped, so it trails the cursor without queueing. Never `behavior: 'smooth'`: its browser-chosen duration is too slow for a key repeat. The target comes from an instant `scrollIntoView` that is undone before paint, so the header's scroll-margin and the pinned column's scroll-padding stay the single source of where a cell lands. Reduced motion keeps the instant jump.
- **Data-grid columns animate through per-column custom properties on the scroller**, never per-cell motion components: hiding or showing a column is instant, no fold; a header drag moves the column with `shift` and slides the others aside; the order commits on release and a FLIP on the same variables settles every column. Nothing re-renders per frame. Each shift is one `MotionValue` written to its variable on change — `animate(element, { '--var': … })` keeps its own per-element value and ignores a hand-written property, so a FLIP set by `setProperty` snaps. The dragged column stays lifted until it lands.
- **Reorderable strips**: `Reorder.Group`, `layout="position"`, animate layout only while dragging — no drift when labels change width. Value identity rules in [gotchas.md](gotchas.md).
- Scroll-edge cues never use JS scroll listeners — `scroll-fade` / `scroll-fade-x` (CSS mask) for plain scrollers — on a kit `ScrollArea` pass it via `viewportClassName` (the viewport scrolls, its scrollbar is a sibling so the mask never clips it). The data table takes no scroll-edge fade: its sticky header and pinned column already mark the edges, and a fade over rows would hide the editor card.
- **Changed cells flash once.** A refetch that changes a value (matched by row identity under the same filters and order) keys a `bg-primary/20` overlay with `animate-out fade-out` over 1.5s; a second change re-keys it so it replays. The flash state clears when the fade ends, so returning to a tab or scrolling cells back into view cannot replay an old highlight. Pure opacity, so a CSS animation is enough.
- **Work that cannot say how far it is sweeps a kit `Progress` with `value={null}`**: a 28% segment runs the 3px track left to right (`animate-progress-sweep`, 1.5s in-out, the macOS indeterminate bar), then the indicator's width settles to the outcome on the house curve: full in `success` for done (the one place a finished run turns green: a long wait ends on a clear yes), full in `destructive` for failed, empty for stopped; the status line beside it turns to full ink with a success tick and the final time ("Copied 5 tables in 12s"). It loops, so it lives only where the wait is long and rare; a short wait is a `Spinner`. Never travelling dots or a hand-rolled loop between two cards: too small to read as progress, and not tied to anything real.
- **Refetching values pulse; only first load gets a skeleton.** A displayed number whose query is refetching keeps its value and dims + `animate-pulse` — gate on `isFetching`, since `isLoading` is first-load-only and a refetch would show stale data with no cue.
- **`MeshBackground` is a bare shader; pages own its entrance.** Auth mounts it immediately so synchronous WebGL initialization precedes the form's delayed entrance animations. Fade the shader in through its wrapper; a mount timer makes compilation interrupt animations already in progress.
- **Marketing reveals and reactions** (`apps/main`): sections rise in as they scroll into view through `Reveal`, a CSS scroll-driven `animate-in` (16px rise on the house curve, scrubbed by `animation-timeline: view()`, off under `motion-reduce`); `MotionConfig reducedMotion="user"` at the root turns motion's transforms off. **One story moves per chapter on its own**: a chapter's `FeatureStage` plays its picture once at 60% in view, while its `FeatureCard`s rest on their finished pictures (`initial="shown"`, also the server render). **Every picture replays on hover**, like Vercel's cards, and on click or tap, after a cooldown. Hover starts on the first real mouse move inside the picture, never on enter: the page scrolls under a resting cursor, so an enter-triggered replay fires on every picture the cursor passes and the page twitches — `onPointerMove` with `pointerType === 'mouse'` and a non-zero `movementX`/`movementY` (Chrome sends zero-movement moves while scrolling), re-armed on leave. A replay never snaps: every `hidden` variant carries the shared `REWIND` transition, so the picture rewinds in a quarter second and then plays. Pictures are driven by animation controls (`usePlayback` in `feature-blocks.tsx`): children declare `hidden`/`shown` variants (`variants.ts`, all on the house curve, entrances 300–500ms), and a play runs `hidden` then `shown`. A story only plays forward and never reverses when the pointer leaves — a hover-held `active` state snaps back on leave.

## Pane folds

`motion-panels` (`monorepo.md`) animates a sized pane's own width/height on the house curve whenever its target changes; the fill pane is plain flex, so one clock moves both. What the app has to get right:

- **Content rides the fold, never a second clock.** A pane forwards motion's presence props to its content block, so a pane fades, slides or scales its contents while the package animates its size; the pane's `transition` prop is the one knob for both. **`initial` doubles as the closed state** — supply `exit` only to leave differently than you arrived, and note that either one hands presence the decision of when the content unmounts.
- The package anchors the content block to the pane's **still edge**, so pivot a `scale` there (`origin-left` before the fill pane, `origin-right` after it) and never add a compensating `translate` — the content does not ride the seam. Never animate the content's own width or height: the package owns them.
- **Content stays mounted** by default once opened, clipped at zero while collapsed, because a remount costs the whole mount before the first animated frame and reads as a click that did nothing (the chat's message list is ~300ms of markdown against a 250ms fold). Keeping is lazy, and a pane already open on first render skips its entrance. Pass `keepMounted={false}` where mounting is cheap and keeping is not — a kept pane's work keeps running while it is closed.
- **Only pin content that bleeds to its own edges.** Pinning (`pin`) lets a Monaco editor or virtualized table lay out once per fold instead of once per frame, but a card with a border, rounded corners or a shadow puts a visible edge at the pinned width — which is why the app's panes, all cards, do not pin.
- Drags never animate: every pointer move jumps the pane and its content to the pointer and stops any running fold; the size commits on release. Under `prefers-reduced-motion` every fold drops to `{ duration: 0 }`.
- Runner results and logger detail are plain `div`s flipping an inline size with no animation.
