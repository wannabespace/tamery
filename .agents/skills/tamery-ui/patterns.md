# Native macOS patterns

## Window chrome

- Window dimming is token-based: `.electron.window-blurred` greys `--primary`, so all chrome dims for free. No transition — AppKit snaps.
- `body` is `overscroll-none`; inner scrollers keep native bounce.
- The window is inset (`p-2`) and never fills the screen, so there are no infinite screen edges to throw the pointer at. The substitute is the surface edge: a control sits at the edge of the thing it acts on, a context menu opens at the pointer, a row's controls stay inside the row.
- The top-left corner belongs to the traffic lights (`trafficLightPosition` in `apps/desktop/src/main/main.ts`). Branding never sits there — near but unaligned with the lights, it reads as a mistake. The auth side panel keeps its logo at the bottom with the tagline and starts below the title bar while the lights show, so no rounded corner or gradient sits under them; on Windows, Linux and in fullscreen the controls are elsewhere, so it keeps the even inset.
- **Minimum window size**: `MIN_WINDOW_WIDTH`/`MIN_WINDOW_HEIGHT` in `@tamery/shared/constants` are the one source — Electron clamps to them and `window-too-small.tsx` covers the app below them (above dialogs and toasts, still draggable). The overlay stays even with the native clamp: zoom and the web build have none. Detection is a module-level seitu media query, never a resize listener.
- **Boot shell**: `apps/app/src/shell.tsx` draws the chrome shown before the bundle loads — one shell per router layout. Keep shell components hook-free and Node-safe, take every class shared with live chrome from an exported const (never a copy — that is why the swap is invisible), and key repeated chrome by data attribute, never id. `boot.ts` re-parses raw localStorage JSON rather than importing seitu (~155kB of render-blocking script vs ~1.2kB); never retype a key or default there. Workspace panels draw into region placeholders (`data-shell-left`/`-right`/`-bottom`), sized from `shell-layout` (region → size of each open panel), which the workspace layout writes. `[data-shell]` visibility rules stay unlayered in globals.css — inside `@layer base` a `display:none` loses to a utility. Dev cannot show the pre-JS paint; check timing against a build.

## Controls

- **Control family** (kit): no border — level-3 fill + `shadow-xs` + hairline `ring ring-foreground/4`, border slot transparent so focus never shifts layout. Hover is `bg-accent`, the one hover surface ([colors.md](colors.md)), never a per-control mix. Focus is `focus-visible:focus-ring`, invalid is `aria-invalid:invalid-ring` — the kit `@utility` pair in globals.css. The focus ring snaps on and only fades out: `focus-ring` drops the control's transition while focused, since a 200ms fade-in reads as lag behind the caret. Focus is always accent and never tinted by state; a control dialing its own `ring-*` pair is the utility going stale, and a `border-destructive` under the invalid ring gives an invalid field more weight than a focused one. Floating panels take the same hairline and `shadow-xl`.
- **Disabled is `opacity-50` + no pointer events on the whole control**, carried by the surface the user sees — a composite control reads the state off its own input (`has-[input:disabled]:`) where the primitive exposes no disabled attribute, or a locked picker looks live.
- **A trigger that opens a menu takes no tooltip** — the menu names its items. Either a button acts or it opens a menu, never `+` plus caret.
- **No bare interactive icons**: ghost hover surface + muted→foreground glyph + tooltip — `Button variant="ghost-muted"` (`outline-muted` for that surface; `ghost-destructive` rests at the same muted glyph and turns red only on hover, so a row's icons read as one set). Upgrade bare ones whenever touching a file.
- An icon-only copy button is kit `CopyIconButton` (`custom/copy-button.tsx`): its `label` is both the tooltip and the `aria-label`. Bare `CopyButton` is for one that carries its own text.
- Any other icon-only button is kit `IconButton` (`custom/icon-button.tsx`): `icon` plus `label`, which is both the tooltip and the `aria-label`, with the tooltip's `shortcut` and `side` passed through. A hand-built `Tooltip` around a `Button` with one glyph is upgraded to it whenever its file is touched.
- Icons are Hugeicons only (`HugeiconsIcon` + `@hugeicons/core-free-icons`, `strokeWidth={2}`). A glyph that flips with state is one icon with a ternary on `icon`, never two branches.
- Shortcuts render through `ShortcutKbd` (`core/keyboard/`, over the kit's `KbdHotkey`) by id, never a hand-built `Kbd`; a key is a Hugeicons glyph, never the unicode character — ⇧ is `ArrowUpBigIcon`, never an arrow that reads as ↑; ⌫ has no Hugeicon, so the kit draws its own in the same stroke, never the trash can. Modifiers follow macOS order ⌃⌥⇧⌘ (⇧⌘E, never ⌘⇧E). A `Kbd` sizes itself to its host: full size inline, compact (`h-4`, `text-2xs`, 10px glyphs) inside a tooltip or a menu row's shortcut slot, so call sites pass no size. A `Kbd` has no background anywhere — a tinted chip vanishes on coloured buttons and dark surfaces, so shortcuts read by muted text alone. **A button never draws its shortcut in its label** — not a `Kbd`, not a hand-rolled `Esc` span: the hint lives in its tooltip (next bullet). Search fields keep their always-visible ⌘F hint in the field's end slot.
- A key drawn as a physical key is `Kbd variant="keycap" size="lg"`, animated through `KbdMotion`, never a hand-built raised span.
- **Holding ⌘ shows each control's shortcut glyph, nothing else.** A control with a shortcut passes its `Kbd` as the kit `Tooltip`'s `shortcut` prop, never inside `TooltipContent` (the kit appends it); pass nothing while the control is disabled or the key does not fire here (`window.electron && <Kbd…/>` for Electron-only keys). Hover shows the label plus the glyph; once `useShortcutReveal` reports ⌘ held for a beat (never, while the user has turned it off in Settings → Keyboard), the tooltip opens with the glyph alone, so neighbouring controls' hints stay small and apart, and nothing reflows. A control something else covers (under an open menu or dialog) shows no hint — the kit hit-tests the trigger as the reveal starts, so a menu shows only its own rows' shortcuts. Pressing a shortcut mid-hold ends the reveal until ⌘ is held again, since the dialog or menu it opens would otherwise sit under hints already shown. Two hints that still meet take different `side`s. A control that only appears on hover (a tab's close button) also takes `data-popup-open:opacity-100`, or the hint points at nothing. A text button with a shortcut gets a tooltip for it too — the tooltip exists to carry the hint.
- **Nav fires on mousedown** (`~/components/link.tsx`, never router `Link`); menu items activate on click (macOS semantics). Imperative press-nav uses `pressNavProps`.
- Tooltips never nest triggers, and multi-node prose goes in **one** block child — `TooltipContent` is `inline-flex`, so sibling nodes lay out as columns. Rich content (a card with icon, heading and paragraphs) is never a tooltip: it is a `Popover` with `openOnHover`, so it gets the popup surface instead of the inverted tooltip ink.
- **Column facts read as SQL clauses**, one per line (`PRIMARY KEY`, `REFERENCES users(id)`, `NOT NULL`, `DEFAULT now()`), never paraphrased labels or constraint names: the audience reads DDL, and invented wording is what they cannot parse. The one exception is `NULLABLE`: a bare `NULL` reads as a value. Set as code with keywords dimmed and identifiers and values at full ink, so the eye lands on what differs per column.
- A `link` button owns its horizontal padding; `px-0!` at a call site is fighting the kit. A lone text action under prose (not in a row of buttons) is `link-muted`, so its glyph starts on the text's edge, and its hover only underlines, keeping the muted colour; a ghost button's padding insets it, and an outline adds a box the prose doesn't have.
- **A secret is masked unless revealed or being edited.** A one-line secret is kit `PasswordInput`. A multi-line one (an SSH private key) is a textarea while empty, focused or revealed, and otherwise a read-only one-line password input showing its first line, where a paste replaces the whole key: a password input drops line breaks, and a masked textarea scrolls to its caret and shows partial lines. An eye `IconButton` flips it, the same glyph pair as `PasswordInput`.
- **Leaving Edit with unsaved changes asks first**: a router blocker opens an `AlertDialog` (Keep editing, destructive Discard). It ignores the save's own navigation and never vetoes `beforeunload`, which in Electron cancels closing the window with no prompt. Create and the unlock form don't ask: nothing there is a saved record to lose.
- Rows that repeat a label inside another card (the SSH tunnel's Host, User, Password) keep the short visible label and take an `aria-label` naming their group (`SSH host`), so a screen reader tells them from the server's rows.
- **A one-of-few choice inside a form is a flat `Select`** (below). `Tabs` only switch panels; a row of outline buttons with one filled reads as several actions.
- **A control that submits itself shows its own pending state.** With no button to carry `LoadingContent` (a code input that verifies on the last digit), a muted `Spinner` sits beside the control, positioned out of flow so nothing shifts, and stays through the navigation that follows the request — a dimmed input alone reads as frozen.
- **A server-rendered data page awaits only what its header needs.** The loader awaits the cheap metadata (name, description, filters, so the page head and title are real) and starts the slow read without awaiting it; the table is its own Suspense boundary whose fallback is the kit `TableSkeleton` (`@tamery/table`) inside the same box, and a header line fed by the read (an updated time) gets a skeleton bar of its exact line height. So the server streams the real header with the skeleton at once and nothing above the table moves when rows arrive. A page-level skeleton cannot know whether the optional header lines exist, so it always shifts something. A re-sort keeps the page: the read uses a `useDeferredValue` of the search, the old rows stay, and the table skeleton covers only the grid on a 150ms CSS delay so a cached sort never flashes.
- **A nav link answers the click before the page does.** Its active state follows the pending location the moment it is pressed. The page area hands over to the route spinner only after a beat: while a different path loads (`status === 'pending'` with a changed pathname, so an invalidate or a search-param change never counts), the page fades out and the spinner fades in, both on a 150ms CSS delay, so a cached page swaps with no flash and only a slow one shows the loader. The router's own pending component never appears here — navigation renders in a transition, which keeps the old page up instead of showing a Suspense fallback.

## Popups and menus

- Context menus are always `AppContextMenu` (data-driven node tree; base-ui on web, native menu over IPC on desktop), never raw kit menu primitives. Destructive item last, after a separator. Every action item and submenu carries an `icon` (hugeicons data, not a node); native menus show its SF Symbol twin from the `sfSymbols` map in `AppContextMenu` (macOS `nativeImage.createMenuSymbol`) — a new icon needs a map entry or it renders web-only. Names are typed (`SFSymbol` from `sf-symbols-typescript`), but the type covers the newest SF Symbols release: a symbol newer than the running macOS still renders empty, silently. Leaf lists that read as options (filter operators, radio choices) stay icon-less.
- A function `items` resolves when the menu opens, on web and native alike, so one menu per card can pick its items from a ref the right-click just set (the diagram's table/column menu).
- **Open in New Window** is the first item of any row menu standing for a route, above a separator. The target must exist before the window opens (a table registers its tab first); `openNewWindow` takes the route href. Secondary desktop windows open offset and never restore maximized — landing on top of the window you came from reads as nothing happened.
- Popups keep the kit's density and radius — don't re-inflate or shrink. `DialogContent` is `p-5` with a `gap-4` grid; the registry's `p-6 gap-6` read as empty against the app's row heights (`AlertDialogContent` still has it). `PopoverContent` owns padding through its `padding` prop (`none` also flattens the base-ui viewport slot); a call site writing `p-0` plus a slot override is the prop going unused.
- Popovers keep 8px off the window edge and never outgrow the window; a wide fixed-width popover shrinks instead of hugging the edge. The kit caps the height at `--available-height` too, so a tall popover's scrolling body must be a `min-h-0` flex child, or it overflows the cap instead of shrinking.
- Popovers size to content (`w-auto min-w-40`), menus cap at `max-w-80`; only `Select` and `Combobox` match `--anchor-width`, since a menu row is usually longer than its trigger. `CommandInput` only at ~8+ items; hide a sole group heading.
- **Command popups**: state lives as rows in the one `CommandList` — a pinned block outside it is invisible to filter and arrows. The row is the button (state = glyph on the row), a two-state control is one flipping icon, and a picker belongs in the same popover's body, never a child popover. A hover-only ✕ is never the only way out; a nested trailing control `stopPropagation`s on `onPointerDown` *and* `onClick` (cmdk selects on click) and sits absolutely inside the row.
- A hidden control still holds its space, and a control that only appears on hover never moves out from under the pointer.
- **Dashboard rows are one ↑/↓ list** — Last Opened, the connection rows and New connection — entered with ↓ from an unfocused page; a focused connection row takes the hover fill plus an inset focus ring, since the card clips an outer one.
- The `AppMenuButton` ⋯ is always visible in dashboard rows, definitions tables and column headers. Only the navigator's sidebar rows reveal it on hover, because the row's pin can take its place there. A row or header carrying a ⋯ also opens the same items on right-click (`AppContextMenu` on the row or header, one shared `items` function).

## Lists and tables

- Grouped lists: one `rounded-xl border bg-card` container, `border-b last:border-b-0` rows, `hover:bg-accent`.
- **A page list's search gets its own full-width row** under the count and controls row, at default size. Squeezed among the controls it truncates its placeholder; stripped of its surface it stops reading as a field. Matches are highlighted in the rows.
- **Labels align by text, not by block.** A page title or heading over a card or list takes the rows' horizontal inset, so its first letter sits on the same line as the row text below — never on the card edge, never on a padding of its own. Change the row padding and the heading's inset moves with it: over `sm` Items (Settings rows) the heading, header row or inset `CodeBlock` takes the kit's `smallItemInsetClassName`, never a copied `px-3.5`.
- Data table: ghost cell controls only (outline buttons down a column fight the values); **a hairline grid, no zebra**: every row takes a bottom rule and every column, header included, a right rule (the gutter and the trailing column take none), since cells edit in place like a spreadsheet. Hover stays `bg-accent`; the skeleton draws the same rules. Skeleton bars are deterministic (`pseudoRandom` seeded by index), never `Math.random`.
- **Data table cells read as sans** (values are data, not code); only the editor's JSON/XML view is Monaco. The cell cursor ([colors.md](colors.md)) is the grid's keyboard home. One context menu serves every cell, resolved from the cursor the right-click just placed — never a menu per cell.
- **Header = property row**: one line, the column's kind as a muted glyph before the name, like a Notion property — the DDL clauses live in a tooltip, never as a second line. The resize grip ends on the column rule at full header height, never past it (see [gotchas.md](gotchas.md)). **Clicking a header cycles its sort** ascending → descending → off: an unsorted column replaces the sort (⇧-click adds it as the next level), a column already in the sort cycles in its place and keeps the rest, so a stray click never wipes a multi-level sort. The press is the drag's too: past a few pixels it reorders instead (cancelled or not), and the header's own controls (⋯, grip), its portalled menus and a press that closes an open cell edit never sort. The keyboard route is the column menu.
- **Values render by type**: booleans are a kit `Checkbox` flipped in place — never a text editor; enum values a secondary `Badge` led by a coloured dot (Finder tags; the hue lives on the dot only, so the chip text reads in both themes; colour = the value's position among the column's values, else a hash); a multi-value row of tags that overflows the grid cell fades out at its right edge (a mask, not a measured `+N`), so a clipped chip reads as "more", not a rendering bug; numbers, dates and times left-aligned `tabular-nums` (a column of values reads from the left); a time whose stored offset differs from the viewer's keeps the stored text first at full ink (what the engine holds is what people read the grid for) and follows it with the viewer's wall-clock time, muted, its tooltip naming the zone (no glyph: the muted second time already reads as a conversion), dated only when the day differs; NULL a muted `null`.
- **Editing is a level-3 card over the cell**: a `Popover` anchored on the cell with `sideOffset` of minus the cell's height, so it covers the cell from its top-left and base-ui's collision handling flips it up (bottom on the cell's bottom) or shifts it; at least the cell's width; the cursor ring hides while it is open. Text is a flat growing `Textarea`, dates and times included (no calendar: timestamps are typed or set with `Now`); enum values open a tag `Command` list as wide as its longest value (window-capped), since enum values often share a long prefix and a truncated tag cannot be told apart; JSON and XML open Monaco. A foreign key opens a server-side search over the referenced table matching the key and every text-like column, so a person's name finds their id; each option is the key over a muted preview of the row, and Enter on no match still saves what was typed. An untouched edit lists the current value first, so Enter keeps it. A nullable, editable column always ends the card with **Set null**, the one way to NULL in every editor. The edit's text lives in the cursor store, so it survives its row scrolling out and back.
- **An edit commits like a Finder rename**: clicking anywhere else applies, leaving the window does not. A rejected value keeps the card open with an inline destructive message, never a toast — except a foreign key's search card, whose text is a search, not a value: no row matching is said by its list's empty state, and a type error under "No matching rows" would only repeat it in the wrong terms. Enter with no match still applies a well-formed key (the engine judges the constraint, which may be deferred or unenforced); malformed text just stays in the search. A column whose DEFAULT the engine can write back in an UPDATE offers **Default**, shown in the cell as italic `default`. The keys are the spreadsheet's (`docs/features/table-browser.mdx`).
- **Cell blocks are spreadsheet selections**: copy and paste move TSV, one value fills a block, and rejected pasted values are counted in one toast. A right-click inside the block keeps it. Two or more selected cells add a summary (count of filled cells; sum, average, min and max for numeric columns) to the grid's bottom dock.
- **The grid's bottom dock holds pending and selection actions, never the toolbar.** One glass bar centred over the grid's bottom edge (`GridBar`), its items in a fixed order: the cell-block summary, checked-row Delete, then unsaved changes (Review, Save), so the primary action ends the bar on the right. Conditional actions in the toolbar would push the filter field sideways; the dock keeps the toolbar still and sits by what was selected. Callers pass items through `DataGrid`'s `bar`; the summary is the grid's own. Review is `ghost-muted`; Delete (`destructive`) and Save are filled — a ghost button's invisible padding makes the dividers look unevenly spaced. Counts on its buttons are a `NumberFlow`; the selection summary's stats are plain `tabular-nums` text, since they change on every arrow press and rolling digits there read as noise. A stat past a million shortens (compact, then scientific from 10¹⁵, where compact would grow digits again) and keeps the exact value on hover, so the bar never outgrows the grid; integer columns are summed as `BigInt`, since drivers hand `bigint` over as text and `Number` rounds past 2⁵³.
- **JSON quick look** is a cell-owned popover, so virtualization unmounting the cell takes it away; moving the cursor or editing clears it.
- **Pinned columns** lead the grid in pin order, sticky, opaque and hovering with their row, and a drag never moves them. **Distinct Values** hangs from the header in a table-level popover, never inside the header, whose drag and menu handlers would take its events. **Show Labels** on a foreign key keeps the key first at full ink (it is the stored value, like a time before its conversion) and pins the referenced text column's value to the cell's end as a secondary `Badge`: the key truncates first, since a long id would otherwise push the label out, and the chip reads as an annotation, not the value. The label is capped at two thirds of the cell so the key always shows; the default comes only from a short list of conventional label names, never a guess beyond it.
- **The grid's leading column is pinned to the left edge**: it holds only the row checkbox, one row-height square, and exists only on tables whose rows can be found (`rowIdentity`: a primary key where keys are unique, a unique key with no nullable column, or the comparable columns). Identical rows share one key, so ticking one ticks all of them and the Delete count and select-all count ticked rows, not keys. A new row shows a discard button in that square instead, since the row is not saved and cannot be selected. Scroll padding spans the gutter and every pinned column, so a revealed cell never lands under them.
- **References peek, never navigate**: one peek per grid, anchored to the cell and closed when the grid scrolls ([gotchas.md](gotchas.md)). The ↗ (foreign key) / ↙ (referenced by) buttons are glyph-only ghosts, always visible — a reference is a fact about the value, so it never hides until hover. The popover hangs from the cell itself, not the button. One matching row is a record (fields, then a *Referenced by* list); several are a table whose rows open a record, the matched column dropped since every row repeats it. The header is the trail: earlier hops are crumbs that jump back, no separate Back button, and Escape pops a hop before it closes. Hops swap with an instant exit — a cross-fade layers two tables of different heights. No scroll fades in the peek. The peek is read-only; ↗ inside it always means *show it here*, and leaving for a tab is only the labelled **Open in Table** button.
- A connection this device cannot query opens to the pane empty state carrying the blocking reason and one outline Back, never to the error page. What the user can supply here is not a dead end: missing secrets, or the server details a metadata-only sync never brings, open the connection's own form in place, identity card hidden and every field the device already holds disabled for context, so there is one form for a connection's details, never a separate credentials screen. Name, label and color change only from Edit. Empty states use kit `Empty`; a pane-level one is the kit's icon empty state (icon + title + one line, the app and the share site's one component) on the pane density `Empty size="sm"` (full-page states take the default size) with a `muted` or `destructive` `EmptyMedia` tile — anything added competes with the emptiness, and the emptiness is the message. The one exception is a way straight back to work: a failed runner statement offers "Fix with AI" under the error, and the connection's empty pane lists recent tables under the text as ghost `sm` `Button` links, headed by a muted `text-xs` "Recent" label aligned to the rows' inset. A popover list's empty state is its `CommandEmpty`: a muted icon over one `text-xs` line, no tile, no title.
- A pane-level **error** reuses that scale with a destructive-tinted tile: the title names what failed, the database's own message is the description (mono, masked, selectable), never a generic hint above it, which guesses a cause the message already states. Full text sits behind a ghost `Show details`. An error the user can fix from where they are opens in place with its remedies as buttons (outline for leaving and retrying, filled for the fix), rather than sending them to the error page, so the fix is one click from the cause. A value the app could only guess is left blank until the real one arrives, never shown as fact.
- **Editable value lists** are the kit `EditableList`, never a hand-rolled row stack. It owns the whole keyboard and pointer contract so every list in the app answers the same keys (Enter inserts below the caret, Backspace removes an empty row, ↑/↓ walk, ⌥↑/⌥↓ move the row, Escape blurs, multi-line paste spills, grip drags to reorder), holds itself to one row and marks duplicates itself. A drag reports its order once on release, so a form deriving a plan from the order does not flicker mid-gesture. Ids belong to the call site — a row seeded from existing data carries its own identity while the list mints uuids for rows it adds. The list paints one field surface; the `Add value` button sits **under** the card at the card's size tier, never as a row inside it (a row the user has to read to know it is a button).
- **Documents view is a `DataGrid` layout, never a second table.** Only the body swaps; cells, cursor, editor, cell menu, drafts and references are the grid's own, so a feature added to the grid lands in both. Each document is a run of full-width field rows under a sticky `Row N · <identity>` label (identity is the primary key value, else the first unique constraint's, never a guessed name-like column) — no cards or borders — and the label toggles the row's checkbox. Field labels are the column header in one line and share its menu, minus resize and drag. Arrow axes swap; values wrap and clamp at four lines, and nested JSON opens as collapsibles. The toolbar toggle is one outline icon button whose glyph names the view it switches to, not a latched fill.
- **Filters can go through a foreign key**: typing a referenced table's column offers *Filter by users.email* (`via user_id`), compiled to `user_id IN (SELECT id FROM users WHERE …)`. Its chip reads `users.email`; Copy-as-code hides the ORM formats while one is active, since only SQL can state it.
- **Table toolbar** is a row above the grid like the runner's, on the pane surface (no strip fill), the grid carrying the top hairline; its filter suggestions and menus open downward.
- **Table toolbar counters**: outline buttons sharing one shape, each count on the control that acts on it. **Count always visible, geometry always stable** — `Skeleton` before the count is known (a premature `0` is a wrong answer), `NumberFlow` via the kit wrapper for the changing part, spent state is `disabled` + `disabled:opacity-100`, never a span swap. Invalidate by query-key prefix, never by threading state around to rebuild a key.
- **Review changes is one drawer recipe** for cell drafts and diagram drafts: a pane-density drawer, one card per row or table with a mono identity header at full ink (the column labels below are muted, so the header reads as the row it names), hairline rows, discards as visible ghost `DiscardButton`s (never hover-revealed — keyboard users cannot reach them). A cell-draft card discards on its header, and per change only when the row holds two or more; a diagram card discards per statement. A cell change is a full-width row button — column name and type over `before → after` inline and left-aligned with a long arrow (a centered chevron reads as a breadcrumb), before muted and struck through — and pressing it closes the drawer and reveals that cell in the grid with the cursor on it. No SQL preview for cell drafts: the value diff says it. A failed save's message sits once at the foot of its row's card, never under a change — a row saves as one statement, so the error belongs to the row, and it clears once any change in that row is discarded. Both drawers are `StagedReviewDrawer` with a `ChangeGroup` per card (`~/core/drafts/review-drawer.tsx`); a surface supplies only its groups, description and submit label.
- **A truncated value over a row link gets a tooltip by being a link itself**: the row's overlay link takes every pointer, so the value renders as its own `tabIndex={-1}` link to the same target as the tooltip trigger (muted, `cursor-default`); a plain `pointer-events-auto` span would leave a dead spot in the row.

## Navigator and tabs

- **32px chrome strips** (tab bar, chat header, logger header): buttons `size="icon-xs"` (glyphs auto-size — never add `size-*`), anything full-height sizes to the header's content box with `h-full`, never a literal `h-8`.
- **Tab strip**: Finder-style content-width tabs, active tab a raised notch, type shown by leading icon alone. Labels disambiguate only when needed (schema prefix at 2+ schemas, ordinal from the second query). Trailing cell pinned to the far right. Contextual controls stay mounted and go `disabled`, never unmount. Active state is surface and colour only — a weight bump re-measures the label and the tab jumps wider. The strip is one Tab stop (the active tab, else the first); ←/→ move focus along it and Enter or Space opens the focused tab. A tab scrolls into view when it becomes active or takes focus, never otherwise, so the strip stays free to scroll past the active tab.
- **Pane-edge tab strips** (logger detail, code dialog): `TabsList variant="bar"` — flat full-height cells, active cell reads as a notch in the pane edge rather than a segmented pill.
- Tab rename is double-click (promotes a preview first) and must not resize the tab: unstyled `field-sizing-content` input inside the same container classes.
- **Sidebar holds no action icons** — an action belongs to the surface it changes, not the surface you were looking at. New tab → the tab strip's `+`; a toggle for one of the connection workspace's panes (Query logger) → a navigator footer row, since the navigator is that workspace's own chrome; the title bar holds only what applies on every page (search, updates, the account), plus the **Agent** toggle on a connection, since that mode reshapes the whole window. The one exception is a row's own hover action on the list it heads: a schema row shows a `+` (New table in that schema) and its `⋯` row menu (Rename where the dialect allows, Copy Name, Drop) on hover, in place of a table count. **A row's `⋯` is always its trailing control**; other hover actions (`+`, pin) sit before it. The footer is labeled rows (`SidebarMenuButton`, the navigator's own row; a toggle marks itself with `aria-pressed`), never icon buttons: New query, the Schema ⇄ Tables switch and Query logger. Creating a table or schema is not a footer row — the schema row's `+` and the command menu cover them. **A menu with a single item is just a button with an extra click.**
- Navigator sections pad `pl-2` only; the right inset is the pane's own gutter.
- **The Navigator is the keyboard's home.** An Escape no surface consumed reaches `window` and lands in the Navigator's search field, opening the Navigator if it is collapsed (`navigator/keyboard.ts`), so a surface's own Escape steps must consume the key (scoped `useHotkey`, base-ui dismiss) or the fallback fires in the same press. Both Navigator panels drive their list from the search field like the Schema pages: ↑/↓ move a highlight that starts on the active tab's row (on the first matching table while searching) and holds through menus and focus round-trips until the search or the active tab changes (on the active row, which already carries the selection fill, the highlight deepens it, [colors.md](colors.md)), Enter clicks the highlighted row and ⌘. right-clicks it, so the keyboard runs exactly the row's own click and menu, Escape clears the search. ←/→ walk the tree like Finder's list view, but only once the caret sits at that edge of the search text, so they still edit a query: → expands a closed schema, steps into an open one, and on a leaf is Enter (descends); ← collapses an open schema, climbs from a table to its schema, and in the Schema panel goes back to Tables. Opening a table descends: the row's click hands focus to that table's grid (`focusGridWhenReady`); a grid never grabs focus just because it mounted. Escape in the grid shrinks a cell block back to the cursor, then walks back to the highlighted row, leaving the cursor where it was for the return; Escape in an empty filter field steps down into the grid, so the ladder runs filter → grid → Navigator. Arriving in a connection lands in the search unless a page's own `autoFocus` already took focus.
- **⌘. opens the menu of whatever has focus**: the runner's statement menu, the grid's cell menu at the cursor, the option a focused field's `aria-activedescendant` names (the Navigator search's highlighted row, or a cmdk list's highlighted item such as `ActionItem` in the runner's Saved and History, whose hover buttons and menu come from one action list), and otherwise a `contextmenu` dispatched on the focused element (tabs, connection cards). This is the keyboard route to every right-click-only action; a row action needs no hotkey of its own once its menu holds it. A menu whose action swaps its own trigger out (tab Rename) passes a `finalFocus` that only targets that trigger, since base-ui's fallback return target otherwise steals focus from what replaced it.
- **A search field that moves a highlight over a list is a combobox**: `role="combobox"`, `aria-expanded`, `aria-controls` naming an element that contains every row the highlight can reach (a sticky copy included), and `aria-activedescendant` on the highlighted row's control. Without the role and the controlled element a screen reader ignores the active descendant and announces nothing as the highlight moves.
- **An open schema with no tables holds one muted `text-xs` "No tables" line** on the table rows' icon column and at their height — no icon, no button; the schema row's `+` already creates there. Search hides empty schemas entirely.
- **One form per schema object**, whether it runs now or queues a visualizer draft: `core/table/table-dialog.tsx` and `column-dialog.tsx`. Rename schema reuses the New schema form. A statement these forms run that fails shows its message as an inline `Alert variant="destructive"` at the foot of the form, cleared when the dialog reopens, never a toast. New schema is a command-menu action and a muted row closing the navigator's tables list, offered where the dialect has schemas; creating one opens New table in it straight away. New table is the schema row's hover `+` and a command-menu action — never on a table row's menu, which acts on that table only; New view is the schema row's menu and a command-menu action (the `+` stays New table): the table form with extra fields passed as children — the `SELECT` in a fixed-height Monaco box (exactly one statement) and Materialized as an `OptionField` where the engine has them; Add column is a ghost `icon-xs` + in the table tab's trailing header cell; Add row and Add column share the toolbar's + menu (next to ⋯, base tables only), kept out of ⋯ so creating is one visible control, with the `LayoutThreeRow`/`LayoutThreeColumn` pair the toolbar's column counter already uses — never the `Insert*` grid glyphs; Duplicate Row is on the cell menu since it acts on that row. **New rows are drafts**, never statements: staged at the top of the grid with the draft tint on every cell, unset cells reading muted italic `default`, saved by the same Save transaction and listed in the review drawer as a `New row` card of its set values; the leading column's discard button, Discard Row on the cell menu, and the card's discard drop one.
- **The column form grows from its type, never from a mode switch**: picking an inline-enum type (`enum` on MySQL, `Enum` on ClickHouse) opens a kit `EditableList` of values right under Type, and the list *is* the type (spelled on save), so there is no separate Enum toggle. **References** is an optional single-select `Combobox` of single-column primary and unique keys under it, shown only where the engine creates foreign keys and the column has none yet; picking one fills an empty Type with the key's type. A primary key column's Type and values are read-only where the engine refuses to retype a key (`retypeKeyColumns`). Its key list is a whole-resource catalog read, so it loads the first time the picker opens and the empty state says so while it does.
- **One form per thing, too.** Editing opens the creation page filled in, never a second form or a dialog, and reads as editing at a glance: the hero names the item and the primary button says it saves changes. Controls that only create, and settings fixed once saved, are hidden: an edit form shows only what it can change.
- Navigator and definitions rows use muted icons, not primary — distinct glyphs in blue read as noise.
- **Navigator status marks** (a table's row level security) sit inline right after the name as a `size-3!` muted glyph (the `!` beats `SidebarMenuButton`'s `[&_svg]:size-4`) with a kit `Tooltip` (never a native `title`), inside the name's flex span so the hover mask still fades them. Only the non-default state is marked; a mark on every row is noise.
- **A connection's label rides beside its name wherever connections are listed flat** (title-bar switcher, MCP access): muted text right after the name, since two connections often share a name and differ only by label. A list already grouped by label shows it as the group heading instead.
- Title-bar switchers: the workspace menu lists workspaces only; connections and resources are reached through the breadcrumb dropdowns beside it (one menu, one axis). Subscription-gated actions render enabled and route to the upsell modal — the modal is the gate, not a greyed item.
- **The upsell modal is a plain kit dialog**: default `DialogContent` (narrow `sm:max-w-sm`), left-aligned title + a one-line note that support keeps Tamery going, footer `Maybe Later` / `Upgrade to Pro`. No perk list, gradient, glow, hero icon tile or footnote — it is a personal ask, not a landing page. A count limit is not a locked feature: its gate passes a hint, and the modal swaps its title and note for what the limit is and how to free a place.

## Messages, alerts, and status

- Alerts: `variant` carries the tint, and there is one density (pane scale) because an alert always sits inside a pane, form or dialog. A call site passing its own padding, radius, text size or tint is a missing variant.
- **An `Alert` reports what already happened.** What a pending action will do belongs on the action: the submit button turns `warning` (`destructive` when it destroys data), is relabelled to the real verb, and carries the consequence in its tooltip — no alert above it and no confirmation dialog in front of it. A confirmation dialog is only for an action with no undo and no draft to back out of. "This field is locked because the shape lives elsewhere" stays a `FieldDescription`; a tinted box for it costs the real warning its weight.
- **An action the current context cannot satisfy is disabled with its reason in a tooltip, never opened to a dead form.** The reason names what is missing ("This schema has no tables to index."), and the button keeps `focusableWhenDisabled` so it still takes hover and a tab stop — a native `disabled` button fires no pointer events, so its tooltip never shows.
- Global banner: slow and broken connections report there — a page that only spins is the bug. Wording is about the response, never "connecting".
- **Server banners paint from the last list.** The fetch waits a beat after boot, so the previous response (localStorage) is the query's `placeholderData`: a banner that was up last time is there on first paint instead of pushing the chrome down a second later.
- **A tab-wide shortcut binds app-wide, not on one element.** Only the active tab's route is mounted, so ⌘Z over staged table edits uses `useHotkeys` with `ignoreInputs` and no `target`: a `target` binding goes deaf when the focused control unmounts (removing a filter chip drops focus to `body`).
- Toasts use `unstyled: true` + the glass recipe. A title-only toast centers its icon, title and button in the row; one with a description top-aligns, the icon sitting on the title's line. **The `Toaster` portals to `document.body`** — `#root` carries `isolate z-10`, so anything inside it paints under body-portalled overlays whatever its z-index; the list sits at `z-60`, above overlays and below the window-too-small cover.
- **A control a guest cannot use stays enabled and dimmed, never hidden** — `opacity-50`, label and tooltip unchanged, no per-control hint. Its press, shortcut and palette entry run the same path a free user's does: `checkOrUpgrade` (`architecture.md` → Permissions). Never `disabled` — a disabled control swallows the press, and the press is the prompt. A locked `Link` takes `disabled` (TanStack drops the navigation but still runs `onClick`). Native context menus can't dim, so their items just stay enabled.
- **Guest limits live in the global banner, never a toast or dialog.** A guest always sees one info banner ("Many features are disabled until you sign in." + `Sign in`) that stays mounted so the guest sees what signing in unlocks; its main text never changes — `font-medium` in the info tint. Hitting a limit appends one regular-weight line after it in the same tint at full opacity (a dimmed tint reads as muddy) — the feature's hint, or a server refusal's own message — fading in and replaced by the next hit, and shakes the banner gently (±4px, 300ms; reduced motion: flash only) and flashes it. Replacing the main text with the reason reads as noise. A toast reads as a missable notification and a dialog is too heavy for a limit the user will hit again.

## Filter field

Suggestion order is JSX order (`shouldFilter={false}`) — the literal answer first, `Ask AI` last. Chips scroll in a capped row so the field never grows forever, and read as prose (`Is not null`), never raw SQL. AI results report inline as a pinned header above the list, never a toast and never inside the scrolling list. Quota exhaustion disables the `Ask AI` item alone, never the input. Blur keeps the in-progress stage; only Escape steps back.

## Panes

- **Pane splits** (navigator, chat, query logger): kit `ResizableGroup`/`ResizablePanel`/`ResizableSeparator` over `motion-panels` (`monorepo.md`; styling only in the kit wrapper, [gotchas.md](gotchas.md)). Sizes are pixel numbers, exactly one pane per group is unsized and fills the rest, and state is controlled: `size`/`onSizeChange` fires on release, `collapsed`/`onCollapsedChange` on a drag past half of `minSize`. The route keeps both in seitu values with bounds in `lib/constants.ts`, so persistence is the callback itself.
- **A width is a habit, not a property of the database** — pane sizes are global, not per resource. The runner's results split is the exception: its height sits in the per-tab runner store, because that pane's open state is already per tab.
- The separator is an optional sibling between panes: a sized pane is always draggable by its edge, the separator only adds the visible grip, keyboard and double-click. It takes no flow space (a zero-width slot at the seam, its grip hanging over the sized pane's gutter) and no side — the package derives direction from the pane it sits beside. Where two seams meet, a press within a few px drags both, and hover feedback is shared: one grip lighting alone while two move reads as broken.
- Folds, drags and every size change animate in [motion.md](motion.md).

## Chat panel

- The header is the chat's share of the window's top row — same height and muted ghost buttons as the tab bar, so both read as one line. Width persists globally; the open chat id is `sessionStorage`, not the resource store, so a second window of the same connection opens its own chat.
- The toggle lives in the tab bar's trailing cell and ⌘L with it, not with the panel. Without a subscription both open the upsell modal — the button stays enabled, the modal is the gate; while the subscription query is pending the pane opens as usual.
- The chat mounts on open and unmounts once the exit slide ends, so nothing runs behind a closed pane.
- Composer textarea owns the whole box with the send control floating over it (an addon row leaves the box's bottom unclickable). Assistant turns render **every** part (a text-only join loses tool work); user = bubble, assistant = bare `Response`.
- First-token wait is a `Spinner` inside the last turn's item — never a skeleton (length unknown), never its own item ([gotchas.md](gotchas.md)). It tracks the request (`submitted || streaming`, the pair that arms stop), never "the last turn is unanswered": a turn that failed before its first chunk persists nothing and would strand the spinner forever.
- Switching or starting a chat aborts nothing (streams detach server-side); the stop button is the only abort. Title falls back to the first user message before `New Chat`.
- Stream failures report inline above the composer as one `Alert variant="destructive"` with `Retry` in `AlertAction` — never truncated, never a toast. Session expiry still toasts and signs out.
- The chat suspends on its collections (`useLiveSuspenseQuery` under a skeleton), never `useLiveQuery` plus a hand-rolled ready gate — zero rows is ambiguous until sync lands, and the resume decision needs real rows (`api.md`).
- **The side panel and agent mode are one chat**: one session hook (`use-chat-session.ts`) and one body (`ChatConversation`); the panel adds its header, agent mode puts the same body full width with the message column, error and composer capped at `max-w-3xl` and centered. Both read the same active chat, so switching modes keeps the conversation in front of you.
- **Agent mode reuses the workspace chrome, never a new layout**: the Navigator region shows the chat list (search field driven by `useNavigatorSearch`, so ↑/↓, Enter and the Escape ladder work as on Tables; footer rows New chat and Query logger), the tab strip shows the open chats with the same tab look (`tabClassName`, `TabIcon`, `TabClose`) and ⌘W, and its trailing cell is a `+` for New chat. The unsent draft is a tab only while it is the active one. The side chat pane collapses without forgetting it was open. Its toggle is the one connection-only control in the title bar: a kit `Toggle` labeled **Agent** (pressed = on, icon in `text-primary`), because the mode changes the whole window, not one pane.
- **Tool calls read as a line, results as a card.** Every call is a disclosure line (verb + connection, a status on the right: spinner while running on the last turn, `Not run` on an earlier one, `Failed`, `Needs approval`), with its SQL and error inside. A query's rows sit under it as a level-2 card (`bg-background`, hairline ring) holding the shared results grid, at most eight rows tall, and a footer with the row count and **Open as Query**, which opens the SQL in a Query tab and leaves agent mode. A pending change is the same card with its SQL and **Decline** / **Run**; Run turns `destructive` when the statement drops or deletes and says so in its tooltip. The card replaces any confirmation dialog: the chat is the place the decision is asked. The planner's row estimate sits under its SQL as the same muted line the MCP dialog shows (`WriteEstimate`). A proposed schema note is the same card around an editable `Textarea` with **Dismiss** / **Save**, so the user can fix the wording before keeping it; its line reads `Needs review` while it waits. A step-capped answer gets a default `Alert` above the composer with **Continue**, in the place a failed answer's **Retry** sits.
- **The composer's `@` and `/` menu** floats above the composer as the filter field's suggestion panel (level-3 popover surface, rising 8px), a kit `Command` with `shouldFilter={false}` grouped into Commands, Connections and Tables. Focus never leaves the textarea: arrows, Enter/Tab and Escape drive the menu only while it is open, and Escape dismisses it for that text only.

## SQL editor

- The runner's toolbar is a row above the editor, on the editor's own surface (no strip fill), in strip-sized `sm` controls: outline **Run all** (play icon, ⇧⌘↩ in its tooltip) on the left, flipping to **Stop** while a run is in flight; muted ghost buttons on the right in three groups split by vertical `Separator`s like the tab bar's (Format and Save tab as query | the **History** and **Saved** popovers | the results toggle) — its state is the icon flipping (panel open/close), never a latched fill. Editor and results share the pane surface, so the editor carries a top hairline under the toolbar and the results panel one of its own — the resize handle alone is invisible until hovered. Running or saving one statement belongs to the inline group after the statement under the caret, not the toolbar. While the tab holds a transaction open, outline **Commit** and **Rollback** follow Run all after a vertical `Separator`, and vanish once it ends: their presence is the open-transaction indicator, so no badge or label repeats it. A transaction the database marks failed keeps only Rollback, in `warning`: that colour is the failed indicator, and a Commit that cannot commit is never offered.
- **No gutter run glyphs.** The statement under the caret carries a faint whole-line band and a `Group` of two outline `icon-2xs` buttons (Run, Save statement; shortcuts in their tooltips) that sits in injected blank text after its terminator, so typing pushes it along and word wrap carries it; it hides while text is selected or an AI card is open, and a caret on a line of its own belongs to no statement. Inside a `BEGIN … COMMIT` block the band covers the whole block, the statement whose turn it is gets a second band on top, and the inline group sits on that statement, moving to the next after each run, so the block reads as one unit while it runs one step at a time. The inline group is **Run** plus a `⋯` `AppMenuButton` holding every other statement action (Explain where the dialect has it, Edit with AI, Save statement), shortcuts shown on the menu rows — no separate hint block. While ghost text shows, Accept/Dismiss sit in their own group before it, never merged with the statement's controls; both stay at the statement's end unless the suggestion itself ends there. A statement whose last run failed (same start, same source) also gets **Fix with AI** before Run; ⌘I fires it only then, so Monaco keeps ⌘I (trigger suggest) elsewhere. ⌘. opens that menu from the editor with keyboard focus inside it, so arrows walk the rows and Escape returns to the editor. The editor itself has no custom right-click menu: every statement action lives on that ⋯, and a second menu repeating it for the whole editor reads as unrelated to the text.
- **AI rewrites land in the editor, never in a diff popup**: the replaced range gets a primary-tinted band and a level-3 card above it holds the prompt (⌘K) or Accept/Reject. The prompt is the kit `InputGroup` + `InputGroupTextarea` (the chat input's recipe: icon and a ghost ↵ send button with a tooltip, absolutely placed top-left and bottom-right — a `Kbd` there read as disabled) that grows with its text (the zone grows with the card) up to a cap, then scrolls: ↩ sends, ⇧↩ breaks the line. Pasted images (paste only, no picker, images only) are `xs` kit `Attachment`s in an `AttachmentGroup`, inset to the text column and clear of the send button. The textarea fills the whole card and everything else — icon, send button, images — is an absolute overlay over its padding, so a click anywhere in the card lands in the field. The images and the send button share one bottom bar, so ↵ centers on the image row. ⌘↩ accepts, Esc rejects; the same card serves "Fix with AI" from a failed result or the inline group.
- The results pane is a 32px strip over the table: numbered `TabsList variant="bar"` cells when several statements ran (error cells destructive, SQL in the tooltip), row count and duration in `text-2xs`, then a `SearchInput size="xs"` and a ghost export button on the right.
- History is a `Command` popup (`w-96`) beside Saved: a row per statement run on the resource, mono SQL over muted `text-2xs` meta (relative time · duration, or a destructive `Failed`), newest first; picking a row appends it to the tab. Clearing is the list's last row after a separator, not a header button.
- A write's result is its affected-row count as an icon empty state's title, never an empty table; a result set with columns but no rows keeps its header row, so the shape still reads.
- Saved queries are a `Command` popup (`w-80`): a row per query with its name over a mono preview, append, rename and delete as in-row controls. Saving lives on the toolbar, never in this list. Both popups always show their `CommandInput`.

## Query logger

- A log list, not a card list: full-bleed rows, no hairlines, `hover:bg-accent`, selection at the latched tint — hover and selection must differ ([colors.md](colors.md)). Not Finder-style solid rows (a slab when full-bleed), no zebra, no primary edge bar, no per-status counter chips.
- Status is a dot coloured only for error and pending; success stays neutral, since a column of green competes with the highlighted SQL.
- Rows are virtualized and render their SQL through kit `CodeInline`. Header is title + clear + close; the title-bar toggle (⌘J, registered beside that button like chat's ⌘L) is the way back in.
- Inspecting a row opens a **detail pane beside the list**, never a viewport-wide popover: a `TabsList variant="bar"` over one bare kit `CodeBlock lineNumbers` for the active tab only ([gotchas.md](gotchas.md)), copy as floating glass inside the panel, no ✕ — re-clicking the row closes it. The seam is a hairline on the detail pane, not a gutter: inside one pane an empty gutter reads as rows stopping short. The pane sits at width 0 when nothing is selected, driven straight off `selected` — nothing mirrors the layout in state.
- The bodies are shiki, not Monaco: an editor instance for a viewer, and no folding (shiki cannot, and hand-rolling it is an editor feature in kit code). Line numbers come from `CodeBlock`'s `lineNumbers` prop as a CSS counter, so selection and copy stay code-only without `select-none`. Params and results print indented, one value per line, length-capped before highlighting.
- The `Tabs` root wraps the whole logger and the active tab is state keyed to the shown query id — never a `key` on the root, which holds the virtualized list.

## Code dialog

One modal, no sidebar: `Dialog variant="panel"` (the kit's full-bleed surface, so the call site writes no padding, gap or max-width). A title row — masked table name, segmented `Tabs` centred, `DialogCloseButton` on the row's centre line — sits over the query-logger detail recipe. The block takes `size="xs"` and `wrap`: a modal exists to read code, and a masked scroller would simply cut an overflowing line. Formats a dialect lacks are hidden, not disabled. No Monaco — a viewer, not an editor.

A list row whose value is code of any length (a logged SQL statement) never prints it inline: the row keeps its one-line summary and puts a ghost-muted `IconButton` (code glyph, tooltip naming what it shows) before its trailing timestamp, so the timestamps stay aligned down the list, and the button opens this dialog, with the raw text behind Copy and the formatted text on screen. An inline excerpt, however truncated, turns a list of events into a wall of code.

## Seed panel

- A right-side `Drawer size="sm"` — **`sm` is the drawer's pane density**, carried through the drawer's context to header, title, description and footer, so a call site never re-dials them. A drawer with a Cancel button still gets the corner ✕ every other window has.
- It is a master–detail inspector: a column list on the left showing each column's current generator as trailing muted text (the whole plan readable at a glance) — a flat kit `Command` without input (`disablePointerSelection`, so hover never switches the inspector) whose `value` is the selected column, never a hand-rolled list with its own arrow handling — the picker for the selected column on the right as an inline kit `Command` with `CommandInput variant="flat"` (the default pill reads as an orphan on a flat pane). Never a form of per-column dropdowns — a column of triggers reads as a settings form and a popup per row hides the choice.
- **Search reads the label and matches by substring.** cmdk's fuzzy default scores the item `value` (the generator id) and surfaces rows whose label shares nothing with the query, with nothing to highlight; a `filter` doing `includes` on the label matches the navigator's own search and marks like it.
- **The list is the only thing that stretches** — options and preview are `shrink-0` at the bottom and the `Command` takes `min-h-0 flex-1`, so the slack lands in the one list long enough to use it.
- The preview holds three sample values in state, not recomputed in render (sampling in the body rerolls on every unrelated re-render); a ghost refresh button reseeds them.
- **The inspector is keyed by column id**, not each stateful child by its own prop — one inspector stays mounted across selections, so state inside it must be reset at the top or it leaks between columns that share a generator.
- **The picker chooses exactly one generator; NULL mixing is a toggle, not a choice** — a modifier on whatever is selected, so it sits in its own section under the list (nullable columns only) and never enters the `Command` list. The SQL expression sits there for the same reason. Never on the column header, the preview header, or as a checkable row in the list.
- **The panel mounts with the drawer, no `Suspense` skeleton.** Nothing sits above the panes; the free-runs quota is muted `text-xs` count plus a `link` "Upgrade" beside the row count in the footer — never an alert row, never a button-shaped chip (a filled pill reads as a disabled control).

## Schema definition lists

One generic page (`DefinitionsPage<T>`) serves Indexes, Constraints, Enums, Functions, Triggers and Policies: sections pass module-level column defs, an `Inspector` component and their DDL.

**Layout**

- Header = title + `NumberFlow` count (skeleton until loaded) + a labeled `+ Add <noun>` button, shown only where the dialect can create — absent operations are hidden, never disabled ([dialects.md](../../rules/dialects.md)). It does go `disabled` until the page knows which schema it would create into: every create form carries the schema, and an empty one is a statement nobody can write.
- Controls row, then a level-3 card holding the kit `Table` at its one density; the page writes no surface classes of its own. Muted header row, hairline separators, no zebra. The card carries no side padding so hover and selection run edge to edge.
- **`table-fixed`: every column but one declares a fractional width and the last takes the slack.** Fixed layout scales columns together, so a fraction survives a narrow pane where a rem width beside a `w-full` column starves; auto layout sized columns from whatever values happened to load and moved between sections, schemas and the skeleton. The unsized column is the one that genuinely carries length, so the slack lands beside real content. Fixed widths also make the skeleton free — its bars are percentages of a known width.
- **Identifiers render `font-mono`, prose labels do not** — names, tables, columns, roles and expressions are values; Type/Timing/Event are chrome. Type is a muted text column, never a badge; state (`Disabled`) is the only badge. Cells `truncate` (the inspector holds the full value), and trailing meta columns take `align: 'end'` for a right-hand rail.
- Rows never animate ([motion.md](motion.md)). Empty = the icon empty state with the section's navigator icon; wording distinguishes "schema has none" from "nothing matches".

**Keyboard**

Lives in the search field: ↑/↓ move the highlight, Enter opens the highlighted (or first) row, Escape clears the search then blurs, ⌘N adds, ⌘D drops the highlighted row (document-level, off while an overlay is open). The highlight is a keyboard cursor, **painted only while the search field holds focus** — a row left tinted after focus moved reads as a stuck selection.

**Capability gating**

- **A capability gate has to match the statement that will actually run, item shape included** — where one dialect edits one shape and not another, the section narrows per item and the form goes read-only with a `FieldDescription` saying why. An operation the database cannot perform must never reach an enabled control; refusing it after the form is filled is the bug.
- **What the engine cannot `ALTER`, the section replaces** (`<object>/recreate.ts`), and **the submit button is the only place the form says so**: `Inspector`'s `warning` prop relabels it to the real verb, turns it `warning` and puts the consequence in its tooltip. **Every path that is not a plain in-place `ALTER` carries one** — a drop-and-add rename, a function or trigger save that drops first, a column-bound enum that blanks rows holding a renamed label. Where two apply, the rarer and more destructive wins.
- Notes about what a save will do *while the user is still editing* stay muted `FieldDescription` prose beside the field that decides it, tracking the edit and never going blank — a description that disappears reads as a bug. The failure the database raises is the answer to "can it", not a check to duplicate in the client.

**Inspector**

- Row click opens a right `Drawer size="sm"` at one width for every section, its body the object's form, fields disabled where the dialect cannot edit — "view" is the same surface.
- **One `Inspector` is the whole shell** — title, the scrolling form, the error alert and the footer — so a section writes its fields and nothing else; **the body is a stack of titled `InspectorSection`s**, never a flat list of fields: micro-title plus a `description` heading a full-width field stack, hairline between sections. Never a left prose rail — it squeezes the fields and sits empty for sections with little to say.
- Sections are General (name, then the one choice that reshapes the object) · the object's target · its options · the read-only SQL of an existing object, which is a titled section like any other with a `CopyIconButton` in its `action` slot, drawn on the field surface so it reads as one more field ([colors.md](colors.md)).
- **Schema is a field of the form, not only the list's filter** — seeded from the list's select, hidden on single-schema databases, locked once the object exists (no engine here moves an object between schemas), and clearing the pickers under it. Creating into another schema by re-filtering the list behind you is the bug: the form states where the object lands, so it owns the choice. A foreign key's referenced schema is its own field — `REFERENCES` may cross schemas, and deriving it silently repoints the key.
- **A picker whose arity another field fixes matches that arity** — offering a chips box that accepts any number, then refusing to save, makes the user guess a rule the form already knows.
- A picker with no data yet says `Loading…`, never `Nothing found.`
- **A cross-section link opens the row, not just the page** — `?open=<key>&schema=<name>` on the tab route, consumed the moment the drawer opens so a reload or a shared URL cannot replay it. The linked schema outranks the one a mounted tab already picked, and the page keeps it when it consumes the link — resolving the row against the old schema finds nothing and drops the link silently. A row key is a JSON tuple, never a joined string: identifiers hold dots too. The drawer opens on a short timer, not on arrival: with rows cached, the tab cross-fade, the row fade and the drawer entrance otherwise run in the same frames and the drawer reads as unanimated (it also keeps the drawer root from mounting already-open, [gotchas.md](gotchas.md)). Its effect depends on whether the linked row exists, never on the row itself — sections derive rows per render, so an effect keyed on the item restarts its timeout forever.
- **The link is inline prose, not a card**: a `text-primary` anchor with a trailing arrow after its `FieldDescription` sentence. A boxed note with a button is a second surface and a second action competing with the footer's save.
- **A link can open a new-item form too**: `?create=<preset>` on the tab route opens the section's form empty, seeded by the preset the section's `getDraft` understands (Triggers → Functions with `create=trigger` returns `trigger` with a starter body). It is consumed with `open` and `schema`.
- **A disabled Add says why on the page**: `createBlocked` renders as a muted `text-xs` line right-aligned under the controls row, never squeezed into it and never only in a tooltip. When the fix lives in another section, the reason ends with that section's link. A section the engine gives no `create` shows the same muted line with no button, naming Tamery as the one that cannot — a missing button reads as a bug.
- Every inspector is keyed by the page's `session` counter so a reopen starts from the row's current values; the drawer shell sits **above** that key ([gotchas.md](gotchas.md)).
- Footer: `Cancel`/`Close` and the primary save, right-aligned. **Dropping is the list's verb, not the form's** — `Drop` lives on the row (context menu, ⌘D) with its confirm dialog, so a destructive button never shares a row with the save the user is aiming at. ⌘⏎ saves (bound inside Monaco too); errors show as an inline `Alert variant="destructive"` above the footer — DDL messages must stay readable, never a toast.
- Row context menu = Edit/Inspect, Copy name, section extras, separator, Drop. Drop confirms in an `AlertDialog` with an optional Cascade `OptionField` where the dialect supports it.
- **Code objects (functions, triggers) are forms too, not a `CREATE` editor.** Name, target, events, timing, signature and execution options are fields; only the routine body stays SQL, in a `BodyField` (Monaco inside a labelled field, fixed height). Which options a dialect offers — timings, events, orientations, volatility, whether the action is a function pick or a body — comes from `capabilities.ts`, so the section never branches on the engine. A row the form cannot rebuild (CLR or table-valued routine, a language we do not write, a body the catalog will not hand back) opens read-only above the SQL section, which stays the place to read what the database actually stored.

**Forms**

- **Every inspector form is a `useAppForm`**, never a row of `useState`s. `defaultValues` comes from the section's `getDraft(item, schema)`, the draft is read back with `useStore`, and everything derived from it is a named `const` in the inspector body — a helper handing back six unrelated booleans hides which branch each control reads.
- Every control sits inside a `form.AppField` so `id`, `htmlFor`, `aria-invalid` and the error line all come from the field name. **The call site writes the label, the options and the prose, never the wiring**: the `*Field` components read the field off context themselves, so re-assembling `Field` + `Label` + control + `FieldDescription` around a picker is a review smell. A field whose change clears others passes `onValueChange` and calls `resetFields`.
- The `<form>` element is the kit's `Form`, which owns `noValidate` and the submit wiring — a raw `<form>` lets the browser's validation bubbles preempt the house error UI. `Inspector` renders it around the sections and publishes it on `formContext`, so a control with no `form.AppField` wiring of its own (Monaco) still reaches `handleSubmit`; the footer sits outside the scroller and its save button submits by `form=<id>`.
- A pick-one row is `field.Select` with its `items`, never a `Select` wired to `field.handleChange` by hand; `field.Select` always shows its own field's value, so a choice that writes more than one field (one option setting two values) is a kit `Select` inside that field's `form.AppField`, its trigger taking the field's `id`, `aria-labelledby` and `handleBlur`; a field that takes a file's text (a key, a certificate) is `field.Textarea` with the app's `LoadFileButton` as its child. A field that takes a file's **path** stays a typed `field.Input` with a ghost folder button in its addon, desktop only: a web file input hands back no path and hides dotfolders, so the button opens the native Open dialog in the main process, which starts in the folder the file usually lives in, shows hidden files and returns a `~`-relative path so the value still resolves after syncing to another device.
- Validation is one arktype `<object>Schema` wired as `onChange` **and** `onMount`, so a form that opens invalid already knows. It covers **every** field a save needs, the required body of a routine included — a `canSave` that also means "complete" is a disabled button in place of a message. **Validate `onChange`, never `onSubmit` alone** — an onSubmit-only validator leaves the form invalid after the first press, so the next press is refused before validation re-runs and every mark disappears.
- **Save is disabled by "nothing changed", never by "not valid"**: a greyed button explains nothing, so an incomplete form still submits, marks every field touched, and says what is missing. Submit gates on `isSubmitting` alone. **A form with no object behind it has always changed** — a create form compared against an empty draft reads as untouched and disables the one button the user came for.
- **What a `changed` predicate compares against is the draft the form opened with**, never the row — the seed normalizes, so a diff re-deriving its own fallbacks reports an untouched form as edited and arms the destructive warning label on a form nobody typed in.
- Submitting owns the trip to the problem: kit `Form` focuses the first field that said no after every refused submit, so a call site wires nothing — a mark on a field the user cannot see is the same dead end as a disabled button.
- **A field error never names a user value.** Its text renders in a portalled tooltip that the field's `data-mask` does not reach, so it says "this schema", never the schema's name.
- **A field error never takes vertical space, and the mark sits on the control that is wrong.** The mark is a `FieldError` in an `inline-end` addon — inserting into the column pushes every field down, which is what made validation read as the form jumping. **Every control that owns a box hosts the mark inside that box**: the field publishes it through `FieldInvalidProvider` and controls with room read it and derive their own `aria-invalid`, so a select and a chips picker mark exactly like an input with no call-site wiring. Only a control with no box of its own falls back to a mark beside its label, and the label hides its copy whenever the control carries one. A call site writes no error element at all. A new or changed message peeks its tooltip for a moment so the user reads it without hunting for the mark; hovering holds it open, leaving closes it. Only one mark peeks at a time — the first in the tree — because the tooltip provider keeps one tooltip open and simultaneous peeks flash through to the last.
- A list of controls marks at the scale of the fault: a duplicate is one row's, so that row rings and carries its own mark; anything the list as a whole rejects rings the box once and states itself once beside the add button. Repeating a list-level complaint per row reads as several faults, and a mark on the section header points at nothing the user can fix.
- **The mark does not animate in** — it is a state, not an arrival.
- Cascade resets use `form.setFieldValue` with `{ dontUpdateMeta: true }` — TanStack Form marks a field touched on every set, so a reset makes pickers complain about a choice the user has not made.
- `onSubmit` calls the section's mutation with `mutate`, not `mutateAsync` — its `onSuccess` owns invalidation, the toast and closing the drawer, so nothing rejects into the form.
- A toggle — in an inspector, a dialog or a page form — is an `OptionField` (`components/option-field.tsx`) holding an `sm` `Switch`: the registry's **choice card** (`FieldLabel` wrapping a `Field`), so title, description and the slack between them are all one hit target ([gotchas.md](gotchas.md)). Never a bare checkbox with a label; checkboxes are for selecting rows.
- **A page form is inset grouped cards, not a stack of boxed fields** (like System Settings): `FieldGroup variant="card"` holds `Field orientation="row"` rows, the label in a fixed left column and the control `variant="inset"` (`Select` takes its `flat` trigger, and a row stretches it, so call sites pass no width), so the row is the surface and only the focus ring draws a box, at the same radius in every row. One card per subject; a toggle that reveals more is the first row of its card, and what it reveals expands inside that card under it (`MotionCollapse` as a card child), never a second card that reads as a second subject. A choice inside a card is a flat `Select` row, never a segmented control: a full-width pill is the one heavy shape among plain rows and runs into the card's corners. When the items need explaining, each is its title over a muted one-line description and the closed trigger shows the pick's description muted after its title, so the choice explains itself where it is made. A row-wide control with no label fills the row. A `Switch` row toggles from anywhere in the row: the row is `relative` and the switch `static` with its own hit-area `::after` stretched to `inset-0`, so the whole row is one target without wrapping it in a label.
- **Form prose is footnotes; placeholders are defaults.** Prose goes in muted `text-xs` footnotes under a card at the rows' text inset, never inside a row, and never repeats the footer's reason. A placeholder shows a value only when it is the real default; an example that is not applied reads `e.g. …`, or an empty field would look configured. A colour picker starts with a "no colour" swatch drawn as a muted slashed circle, sized to the swatches; a bare outlined ring reads as a grey colour. Re-clicking the picked swatch to clear it is a control nobody finds. A free-text value with common picks (a tag, a group name) is a flat picker row like a `Select` row: a `flat` combobox trigger showing the value (muted "None" when empty) opens a popup as wide as the trigger, search on top, "None" first, the known values, and a create item when the query matches nothing, highlighted so Enter takes it. Never an inline autocomplete (its popup only echoes what was typed) and never hint chips under the field.
- **A paste-first page** puts the paste pitch in a sticky left column beside the form cards (stacking below `lg`); the footer passes through the same columns so its buttons end on the form's edge. One hero only: never a centred title over the form, and no card, glow, tinted wash or demo loop behind the pitch. The pitch is a humble two-line headline (full ink over muted; an edited item's long name wraps, never truncates, and the headline grows with it), the paste keys as level-3 keycaps with the platform's own modifier beside a muted "or drop a file", and one muted line naming the formats it reads. A secondary path is a muted text button. Databases the desktop app finds on the machine close the pitch column, under the secondary path so their late arrival shifts nothing: the Recent recipe (a muted `text-xs` count heading over `ghost-tint` `sm` rows, since `ghost-faint` barely shows as standalone buttons on the canvas; engine icon, masked name, muted source trailing), pulled out by the rows' inset so heading and row content sit on the pitch's text edge. A pick goes through the paste path, so it fills, flashes and focuses exactly like a paste.
- **Paste and drop work anywhere on the page**, so there is no paste box and no button to reveal the form: it is always there, and its free main field takes a whole string. A paste that parses fills the form at once and focuses the first missing field; it fills only what it names and keeps what the user typed, unless it names a different target or another kind of place (a server, a SQLite file, Turso, D1), which replaces everything that described the old one; picking an engine with other fields in the Engine select clears the same way, since the same field means something else there and a token must never follow to another host. The Engine select groups its rows under muted **Databases** and **Providers** labels, so a hosted service never reads as one more engine. Each engine's rows come from one table that also decides what is required and what is saved, so a value no row shows is never saved. Inside the form only the free main field reads a pasted connection; any other field takes the text as typed, so a whole string can be pasted there and trimmed down to the one part needed. One footnote under the card names what is still missing and every change the parser made, as sentences in one paragraph, since a silent fix reads as the app mangling the input. A hint that only matters once the test fails goes in the failure alert.
- **A paste that parses nothing** shakes the pitch and rolls both headline lines to the refusal (the refused-action and rotating-line recipes, in a fixed two-line box so nothing reflows), then rolls back. Where the pitch is not on screen it is a toast whose description lists the formats. A paste that parses (anywhere, a field included) rolls the same headline to a confirmation for the same beat, without the shake, so success and failure answer in one place.
- **Switching between a form and an alternative panel**: the old one leaves at once and the new one rises in (opacity + 8px `y`, 250ms), never a slide, an overlap or an exit the next screen waits for, since the fields must exist, focused, the moment the click lands. Choosing the path is the consent, so the panel starts what it needs without a switch. Escape and Back step from the panel to the form first; on the form, Escape blurs, then leaves.
- **Setup an agent runs reads as one terminal session**: a level-2 card with window dots and the client picker in its title bar, then one line per step (a command, a config comment, the prompt), each with its copy button, and a last muted spinner line while it waits. Never a stepper or separate snippet boxes. A secret in a snippet shows masked while its copy button copies the real one, and clients show their friendly name, never a raw id. The panel never claims "connected" on what only proves a client was once seen.
- **Enter in a text field saves the form.** A Save button outside the form (a page footer) is still `type="submit"` with `form={id}`, so Enter reaches kit `Form`, which owns validation and focusing the first refusal; ⌘↩ calls the form's `requestSubmit()` for the same path. A `focusableWhenDisabled` Save still blocks a second Enter mid-save: base-ui cancels the disabled button's click, and with it the submission. Only a form where Enter must not save has no submit button. Page keys bind on a focused `tabIndex={-1}` page root: its native listener runs before a focused control's own keydown, so ⌘↩ on a switch never toggles it. Focus must never fall to `body`: a control that unmounts while focused hands focus back to the root, and buttons that disable mid-action stay `focusableWhenDisabled`.
- **Save tests first.** Where saving something unreachable is legitimate, the primary button runs the test and saves on success; a failure turns it `warning`, relabelled to save anyway, with the consequence in its tooltip, and any edit resets the test. A separate **Test** is a quiet `ghost-tint-muted` button, disabled when this device cannot reach the target, with the reason as muted text at the footer's start. A pass is a small `bg-success` dot before muted text in that spot: a status line, never a green icon with green text.
- **A failure alert is help, not an alarm**: `Alert variant="error"`, a calm level-2 card where only the icon is red. It leads with the cause in plain words and a muted hint; the raw error, which mostly restates the title, sits behind a `ghost-muted` disclosure at the row's end (shown outright only when nothing recognised it). Then one outline `xs` button per remedy and an **Explain with AI** ghost button, whose answer replaces the local hint; it sends only redacted values. It sits in the flow after the last card and scrolls itself into view once, never docked over the fields it is about.
- **A repeated group of fields (SQL Server policy predicates) is one `InspectorSection` per entry**, titled `<Noun> <n>`, its remove verb a ghost `icon-xs` button with tooltip in the section's `action`, and an outline `Add <noun>` button in its own padded block under the last entry. The last entry removes too where the engine accepts none (a SQL Server policy with no predicates). `EditableList` stays the answer for single-value rows.

## Other surfaces

- **Settings** (`/settings/<section>`, avatar menu or ⌘,) is its own layout, like Linear's or Codex's: a sidebar on the window surface — **Back to app** carrying the Esc hint, then a `SidebarMenuButton` per section, the sidebar as wide as the navigator's default so, at the default width, the panel edge stays put entering Settings — beside the active section in an inset panel under its title. `settings.tsx` is the layout and `settings/$section.tsx` renders the matching section's `component` in the panel's `Outlet`; bare `/settings` redirects to the first section, and ⌘, does nothing while Settings is open. It has its own boot shell. Focus lands on the active section, ↑/↓ switch sections (replacing the history entry, so Back never walks through them), and Escape leaves for the previous page, or `/` — bound to the page, not the document, so Escape inside a popup closes only the popup. Sections (component, icon, label, slug) are listed in order in `core/settings/sections.ts`, feature pages included, and the command palette lists every section. A section is `SettingsGroup`s (an optional muted heading over one card) of `SettingsRow`s: title and description left, control right. A `Switch` row passes `htmlFor` so the whole row toggles it; a row with a popup control passes none. A per-item list (one row per connection) drops the description: the title is the item's icon and masked name. A value the user copies sits as muted mono text before a `CopyIconButton`, a secret masked down to its last characters. A snippet to paste elsewhere is an edge-to-edge `inset` `CodeBlock` under a header row (the instruction, any install link, the copy button) — never a copy button overlaid on the code; variants of one snippet (one per client) are kit segmented `Tabs` at the top of that card. Everything inside the card stays on the card's surface: a well or a `bar` strip in a canvas or pane tone reads as a hole cut through to the page.
- **Visualizer loading** is a canvas skeleton, not a spinner: dotted background, the controls and minimap as their real static frames (never pulsing blocks — they are the loudest thing on the canvas), toolbar pills on an opaque underlay so the dots never show through, and a small fixed cluster of ghost cards joined by ghost edges at fit-zoom scale, so it reads as a schema rather than a table and never clips the pane. Row bars stay uniform and everything shares one pulse: a few cards on open canvas have nowhere to hide noise, so jitter reads as debris.
- **An agent's write waiting for approval** (MCP, Ask before writing) is an `AlertDialog` widened to `sm:max-w-lg`, opened from anywhere signed in: the masked connection name in the description, the statement as a `field` `CodeBlock` (`xs`, wrapped, height-capped), then one muted line with the planner's row estimate once it arrives, nothing while there is none. `Decline` takes initial focus, so a stray Enter never commits; `Run` is `warning`, `destructive` when the statement destroys data. Escape declines. A value the user may need to replace (the MCP token) gets a `ghost-muted` icon button after its copy button, confirming in an `AlertDialog` since nothing undoes it.
- **Schema visualizer** (`modules/visualizer/`): React Flow canvas on the pane, level-3 table cards with mono column rows, the toolbar as the table page's `pointer-events-none` dock pinned top-centre (schema, search, drafts, + Table), minimap bottom-right, React Flow `Controls` bottom-left holding zoom in, zoom out and Arrange as `ControlButton`s under kit tooltips (the built-in zoom, fit and lock hidden — Arrange re-lays out and fits), skinned through the `--xy-controls-*` vars on the flow style. Views render as cards with a muted kind tag and no editing; generated and computed columns are read-only too, since restating them drops the expression. Edges are crow's-foot: a bar for one, a fan for many, decided by whether the referencing column is a single-column key; a multi-column foreign key draws one edge. Hovering a card lights its edges and outlines the tables they reach; selecting it lights its edges. **Edits are drafts, never statements**: rename, add, alter and drop mark the card in place (added `success` tint, changed italic on `primary`, dropped struck-through on `destructive`) and stay reversible from the same menu until Apply; the review drawer lists them per table with the compiled SQL, in apply order within each table, and the Apply button carries the consequence as its variant (`destructive` when a table or column drop is queued, `warning` on engines without transactional DDL) and its tooltip. Drop is a context-menu item, never a button; **the review is its only confirmation**, so with any drop queued the toolbar's Apply and ⌘S open the review instead of running. The card's context menu and the inspector's row menus are the same menu. Creating a foreign key is a drag onto a key handle, with the column menu's Reference submenu as its keyboard route; dropping one is the edge: select it and press Delete/Backspace, or the inspector row's menu. Selecting a card opens the **inspector** as a width-animated right pane inside the tab — columns, relations, then Indexes/Triggers/Policies rows linking into the Schema pages with `?open=` — closed by Escape after the search field has emptied and blurred. Node positions persist per schema; draft-created tables land at the viewport centre and stay out of the auto layout so adding one never shuffles the rest. **Built for hundreds of tables**: a pointer move or drag frame re-renders only the cards and edges it touches, and zoomed-out cards collapse to the table name at a readable size.
- **A long job started from a dialog runs inside it.** The form swaps for the job's live log (mono, masked, stuck to the bottom) with the state on the footer's left (spinner plus elapsed seconds, then the outcome) and one action on the right: **Stop** while it runs, **Done** after, plus **Back** to the kept form after a failure or a stop. A failure is a destructive `Alert` under the log naming the error and what it left untouched. Escape is a ladder here too: the first press stops a running job, the next closes. A job that can be stopped safely never blocks the close button.
- **A pick-many list in a dialog is a flat `Command`** inside a level-3 card (`bg-popover rounded-xl ring ring-foreground/4`, [colors.md](colors.md)) with `CommandInput variant="flat"` on top and the kit's trailing tick (`data-checked`) on chosen rows, never a column of checkboxes: one Tab stop, arrows walk, Enter toggles, typing filters. A row that stands for the whole set (**Everything**) leads the list, and only that row selects it: checking every other row stays a list of rows, since the whole set can carry more than its rows.
- **A tool's log in a dialog follows the query logger's row**: one 24px row per step (`py-1`, a 16px line) in an `sm:max-w-xl` dialog so names rarely wrap on the field surface (`bg-input`, `rounded-xl` with the control hairline, as a code block in a form, [colors.md](colors.md)), the object's own icon from the app's set (the navigator's table and view icons, the Definitions sections' key, function, tag and trigger icons; a neutral dot when there is none), then the name in mono with its schema or owning table muted, and the clock time trailing in `text-2xs` muted. No kind words: they differ in width and push names out of line. A failure is the log's last rows (destructive icon and text, its detail under a turn-down arrow), never repeated in an alert; the status line says only how it ended ("Failed. Nothing changed."). Only steps a user would name are shown: no tool prefixes, catalog reads, column or partition plumbing, notices or hints. The log takes space only once something ran, and listens as long as its run is on screen, since a run's last lines can arrive after its result.
- **A dialog that moves something between two places shows the route** under its title, a step further from it than a description line, once it runs: two level-3 cards (`bg-popover`, `rounded-xl`, hairline) side by side with a muted arrow between, each with the engine icon, the connection name at full ink and the database muted under it. A full-width indeterminate `Progress` under the cards carries the run ([motion.md](motion.md)); the status line beside the buttons counts what is done ("Copying 3 tables · 12s"). Never a sentence (`A / B to C / D` reads as four names) or a From/To label grid (reads as a form). The outcome lines below never repeat the names: "Stopped. Nothing changed."
- Markdown is kit `Response` only; the chat does **not** pass `streaming` (per-block memoization restarts the word fade every block). Fenced code and inline code both go through `ResponseCodeBlock` via `components={{ code }}`, tool-part JSON included. A reasoning part with no text renders nothing — Anthropic returns signature-only parts, which would otherwise put an empty disclosure above every answer.
- **Calendar / date range**: kit `Calendar` (registry `@shadcn/calendar`, vendored in kit style). The day cell is a grid square on the kit `Button`, so hover, focus ring and press come from the kit; range ends take `bg-primary` and the middle the latched tint, never `bg-muted`, which vanishes on a popover. `today` is weight and colour only, so it never competes with a selection. Pages import `DateRange` from the kit's re-export, never from `react-day-picker`. A range picker is `Button` + `Popover` + `Calendar mode="range" numberOfMonths={2}`, and needs `w-auto` on the popover.
- **Email sign-in is a code, never a password**: the sign-in form asks only for an email, and its submit ("Continue with email", wearing the `Last` badge like the OAuth buttons) sends a code and opens the code route. That route mirrors the two-factor page — centred heading, `TotpCodeInput` submitting on complete, `link-muted` escapes underneath — and a first sign-in asks for a name there before leaving, the only place a new account gets one. Turning on 2FA ends on the backup codes (mono, `data-mask`, Copy + Done) — the only time they are shown — and the two-factor page offers "Use a backup code" as a `link-muted` escape that swaps the code input for a text field.
- Mesh gradient shader (`MeshBackground`): **auth layout only** — an animated background never sits under a card, and each instance is a WebGL context. Paper shaders parse only hex/rgb/hsl, never our oklch tokens, so a shader takes no theme colour — the panel's `bg-body` shows behind it. Cap `minPixelRatio={1}` + `maxPixelCount`: a full-DPR fragment loop janks the page.
- Floating scroll-to-end control: `variant="outline"`, circle, lifts on hover — the shadow is the feedback; a flat tint over text reads as grime.
- **App icon**: one full-bleed square image, the only icon drawn by hand (the generator in `monorepo.md` → Dev commands derives the rest). The brand mark in a cyan → brand blue gradient (`#5AE6FF` → `#1E8BFF` → `#0050E6`) with its gloss, rim and coloured glow baked in, on a light plate (`#FFFFFF` → `#ECEEF8`), the mark about three quarters of the canvas, a little less in the maskable set so it stays inside Android's centre 80% safe circle. macOS ships it as the single layer of an Icon Composer package with glass, specular, shadow and translucency off: the effects are already in the image, so the system's would double them, and macOS still clips it to its own squircle. Everywhere else it is cut into a rounded square: the Windows/Linux `icon-1024x1024.png`, favicons, `logo.png` and manifest `any` icons. Wherever the icon is shown as a picture on a page or in an email (sign-in screen, download page, email header, README, JSON-LD, Discord avatar) it is the blue tile `logo.png` (white mark on the brand gradient, from the `cyan-inverse` avatar), because the light plate dissolves into white backgrounds; it is served from the public root through `BASE_URL` in the app, which desktop loads from disk, never a hand-drawn SVG. Inline brand marks in chrome stay the `AppLogo` glyph. Icons the OS masks itself (`apple-touch-icon.png`, the manifest `maskable` set) use the full-bleed image as is: iOS fills transparent corners black, and Android crops a rounded icon a second time.

- **The footer is a curtain reveal**: the whole page (navbar and content) is one `bg-body` card with a `rounded-b-4xl` bottom, ring and `shadow-xl`, stacked above a `sticky bottom-0` column footer on `bg-muted`, so scrolling past the end lifts the page off a footer that was pinned underneath all along. The footer tucks up under the card by the corner radius (`-mt-8`), or the corners show the canvas behind them and read square. The footer itself stays plain: link columns and the copyright, no illustration, texture or animation (an etched scene, a dithered image, a giant wordmark and a galloping figure all read as too much). The layout root clips with `overflow-x-clip`, never `overflow-x-hidden`: hidden makes the root a scroll container and both the sticky navbar and the sticky footer stop sticking.
- **Page-scale surfaces** are level-2 `bg-background` cards at `rounded-2xl` with the usual hairline and `shadow-xs`, used only where a card carries content (bento, pricing, the agents demo); the one recommended pricing plan lifts to level 3 (`bg-popover` + `shadow-md`) with the filled button, never a coloured ring; a section's heading and the closing call to action sit on the canvas; shapes inside them are level-3 (`bg-popover`, `bg-input`) or `bg-secondary` for grey bars. One accent, primary blue. Headings are `font-semibold tracking-tight text-balance` (`text-3xl sm:text-4xl` per section, up to `lg:text-6xl` in the hero); no uppercase eyebrows. **A section heading is one two-tone sentence pair**, Linear-style: `SectionHeading` sets the claim in foreground and its explanation in `text-muted-foreground` inside the same `h2`, left-aligned, so no section needs a separate subtitle paragraph. The agents section is the one exception, so the page's rhythm breaks once: a plain heading with its lead in a second column.
- **The hero is a product shot, Linear-style**: one dense, `inert` copy of the connection workspace showing the signature features at once (navigator, tabs, a filter chip, a grid with an unsaved edit and the save dock, the AI chat answering with SQL and a result), server-rendered from the kit components and classes the app uses, with a screen-reader caption. Nothing in it is clickable: a demo the visitor has to operate shows less than a picture that shows everything. When the app's chrome changes, this copy changes with it. The window fills the content column, is cropped rather than shrunk on narrow screens (the page never scrolls sideways), and never stretches past the column. It stands on the page's one shader moment, a mesh stage wider than the text column whose bottom edge crops the window — never a second fade on the stage: stacked masks read as mud. No other section gets a shader; the closing call to action sits on the canvas, since a coloured slab there reads as a template. Only the chat moves, cycling scripted conversations; the server render is the first conversation settled, so no-JS and reduced motion get the finished picture. The window leans back in perspective and straightens over the first scroll, dropped under reduced motion. The hero text is left-aligned with four elements only: headline, one muted lead, two buttons, one quiet proof line (the account count and an Open source link, each led by its icon, only the link styled as one). Never a framed badge above the headline, no avatar stacks (we have no real faces to show), no feature lists or trust strips. The count is in the server HTML; while pending it stays invisible with its height reserved and rises in once it lands — never a placeholder `0` — and is published only floored to thousands. Under the hero the engines are a bare logo strip, the page's logo wall: a wrapping row on phones, four even columns from `sm`, so the logos never leave one alone on a row; Turso and Cloudflare D1 follow SQLite, since they are SQLite in another place.
- **Bento cards are crops of the real app**, `modules/features/`: one `BentoCard` (title and one or two lines on top, an `aria-hidden` picture below) per feature, cells exactly filling a three-column grid, the chat card tall in the middle column. Every picture is a piece of the app's own chrome (the palette, the connection list, the toolbar and grid, the chat panel, the editor, the share page) built from the kit and the shared `components/product` parts, inside one `ProductCrop`: a level-3 window anchored at the same inset under the text and cut by the card's bottom (under a fade) and right edge. A card whose meaning sits at the row's end (sync labels, shortcut hints) crops at the card edge instead of past it. Every picture draws on the one `ORDERS` dataset, so the cards tell one story. **Motion is the feature doing its job, on that real chrome, in under two seconds**: the palette types `ord` and the tables that do not match fold away until the highlight lands on `orders`; the chat streams its answer word by word, reveals the SQL top to bottom, then the rows; the filter sentence is typed, turns into chips, and the rows that stop matching collapse out of the grid; connections arrive one by one until the header flips from Syncing to Up to date; the editor types its `WHERE` line, the suggestions open and the pick shows as ghost text; the share link draws in, the page rises and a value flashes as a refresh changes it; the schema's relations draw between the cards. A plain fade is not enough to explain a feature, and a story that has to be waited through is too much. Typed characters take no width until typed (`display`, not opacity), so a caret follows them. Played as the card scrolls in, replayed on hover; at rest the picture is the finished one, and reduced motion sets it directly. A feature earns a cell, not a wide card, unless its picture needs the width; the draggable schema is the one card that moves only by hand.

It is laid out Linear-style: the heading on the left with a muted lead bottom-aligned on the right, a wide two-window visual on the canvas (no card behind it) whose bottom edge fades out under `mask-b-from-*`, then a three-column row of icon + title + line split by hairlines. ## Docs (`apps/docs`)

The docs site mirrors the web account area: same canvas, same inset panel, so reading the docs feels like being inside the app.

- **Shell**: a sticky `h-14` header on the canvas with no hairline (the brand to the website plus a muted "Docs" to the first page, then search, theme and Download, every control on the `sm` tier), the page nav as kit `SidebarMenuButton` rows on the canvas listing every group (muted until current, group labels `text-xs font-medium` on the rows' text inset), and the page in one level-2 `rounded-2xl` panel. Below `lg` the nav moves into a left `Drawer`. No section tabs: CLI and MCP are a few pages each, so they are sidebar groups.
- **The panel is a `@container`**, so the on-page rail follows the panel's width, not the viewport's: from `@4xl` "On this page" is a sticky rail beside the article (Fumadocs `TOCItem` rows on a hairline track, the current section in foreground with a foreground tick); narrower, it is a sticky glass bar at the panel's top whose `ghost-muted` trigger names the current section and opens the same list in a `Popover`. The bar must be a direct child of the panel, or its wrapper ends the sticky range. `scroll-padding-top` in the docs stylesheet clears header plus bar for every anchor jump.
- **Search is the app's command palette**: `CommandDialog` with the kit's `CommandPaletteInput` and `CommandPaletteFooter`. Until the first results arrive it lists every page grouped like the nav, so typing never blanks the list; once results are in, each page is one group led by its page row (group name in the shortcut slot) with its heading and text hits indented under it, matches painted through the CSS highlight API (`::highlight(fd-search)`), never by rewriting the text. Results render from Fumadocs' parsed `hastContent`, never the raw Markdown. The trigger reads as a search field (`outline-muted`, icon, label and its ⌘K hint), collapsing to the icon on phones.
- **Content blocks are level-3 cards on the panel**: fenced code is a `cardClass` card with the `CodeBlock` and a `CopyIconButton` side by side, no header row (a language label over a one-line command is noise); link cards and Previous / Next are kit `Item variant="card"`. Previous / Next follow the sidebar order. Document prose (`Response variant="document"`) styles bare `p` and `a` only, never an element with a `data-slot`, so kit components embedded in MDX keep their own spacing and hover.
- Section headings show a link glyph on hover or focus that sets the URL to the heading; the heading text itself is not a link.
- **Links show the pointer cursor.** The docs are a website, not the app, so the no-pointer rule stops at `apps/docs`: one unlayered `a[href]` rule in the docs stylesheet beats the kit's layered `cursor-default` on every link-rendered component.

## Share site (`apps/share`)

A public page for people with no Tamery account, and it **looks like the app, never like a web table**: a viewer should see the same table tab the owner shared. Links keep the pointer (like the docs), and nothing on it edits.

- **The page is a centered document** (`max-w-5xl` on the canvas): the share name as a big `text-3xl` heading, the description muted `text-sm` under it, one muted `text-xs` "Updated … ago" line, invisible while the rows are under a minute old so it never reads "less than a minute" (the refresh interval stays off the page, but an open page refetches on it in the background, so a viewer who leaves the tab open sees new rows without reloading), the owner's filters as read-only kit `FilterChip`s (no trailing segment; their segments come from the same kit variants as the toolbar chip's, so a long value caps and truncates in both), all on the rows' text inset. Then the table as one level-2 card (`bg-background`, `rounded-xl`, hairline ring, no shadow) that hugs its rows and caps at the viewport, scrolling inside. Above the heading, one `h-8` line carries only the logo (linking to the website) on the left and the account action on the right: outline `sm` **Sign in**, or ghost-muted **Your shares** once signed in (hidden on that page). The account action streams in through Suspense with no fallback inside the fixed-height line, so the viewer lookup never blocks the page or shifts it. Nothing stretches to fill the window: an app-sized pane around two rows reads as an empty page. No title bar, toolbar, pager, download or "Made with" badge.
- **The grid is `@tamery/table`'s `Grid`**, the one the app's `DataGrid` is built on, with the app's header recipe (an `h-8` cell with no vertical padding, so it matches the table skeleton's header; the kind glyph the app stored with the share, the kit's `ColumnKindIcon`, `text-xs font-medium` name, the primary sort arrow) and cell recipe (`text-xs`, muted `null`, booleans as a read-only `Checkbox`, `tabular-nums` for numbers and dates). Column widths come from the same `getColumnSize`. Rows load as the viewer scrolls, like the app, through an infinite query seeded by the server render. A header press cycles its sort ascending, descending, off. Hovering a header never preloads its sort: that would read the owner's database. A failed later page keeps the rows already loaded and swaps the footer spinner for an outline **Try again**, pausing load-on-scroll until it succeeds; refresh polling stops once a viewer has loaded more than one page.
- **A read-only grid is still one keyboard surface**: the scroller is the single Tab stop and every header link and checkbox inside is `tabIndex={-1}`. Arrows move a cursor with the header as the row above the first, Home/End jump to the first and last column, Enter or Space on a header sorts, Escape leaves. The cursor is the app's inset ring, shown only while the grid has focus within (a read-only grid starts with a default cursor, so an unfocused ring would be noise). Moving glides the cell into view, or scrolls the virtualizer first so an unmounted column mounts; body cells carry a scroll margin the height of the sticky header so they never land under it. A click places the cursor.
- **The owner's share list (`/` on the share site) is the only share list**; the app opens it from the account menu's **Shares** and the dialog's **Manage shares**. It has the same top line, a `text-3xl` "Your shared tables" heading with the signed-in email in its muted line, then one row per share (connection icon, masked name, muted `schema.table`, details or the failing warning) with copy, open and a ghost-destructive stop-sharing that asks in a confirm dialog first; the empty state is the kit's icon empty state (muted glyph, title, one line). Changing a share stays in the app, where the table is. Its list loads from the API, so the route shows a skeleton of the same frame (the real heading, pulsing rows) after 150ms; page and skeleton render through one frame component, so they cannot drift.
- **Every state that is not the table is a status page**: a muted glyph, `text-2xl` title, one muted line, at most one outline action (Try again for an unavailable database). The password state uses the same column with a `PasswordInput` and **Open** side by side, its refusal as destructive text in the muted line above them.
- **Making a share lives where the table is**: **Share** in the table toolbar's ⋯ menu, disabled with a muted trailing "Needs Full sync" when the connection is not synced with Full, since a menu row carries no tooltip, and disabled until the share list has loaded, so the dialog never opens on a stale guess. The share list's empty state says how to make one. One dialog creates and edits. Once the table has links, a select under the header (no label of its own; the header already says what it is) picks one of them or **New link**, and the dialog opens on the link whose saved view matches what the table shows. Then the link (a read-only **Link** field with copy and open) once it exists, then name, description, refresh and expiry side by side, `OptionField` switches for the table's filters (only when it has some) and for a password, which reveals its field under it. A footnote says what viewers see. The free-plan limit is checked on **Share**, not on opening, since editing an existing link is always allowed. Creating copies the link and keeps the dialog open on it. **Stop sharing is not in the dialog**: dropping is the list's verb, so it lives on the share site's list, which the dialog's `link-muted` **Manage shares** opens.

## Two principles behind the rest

- **The target is the whole surface, not the glyph inside it.** A row's hit area is the row, a strip button's is its hover square, a separator's is the grab strip around its line. A control whose clickable area is its ink is a control the user has to aim at.
- **Anticipate the pointer, not the click.** Work the user has visibly committed to is warmed when the intent shows, so the click finds it ready. Hover is for *revealing* — it never navigates, selects, saves or opens a window, because crossing a surface is not a decision. Pressing is, which is why nav fires on mousedown.
