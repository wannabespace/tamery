# Kit gotchas

Upstream traps and the house answer to each. Read before debugging a kit component.

## base-ui / registry components

- `CommandDialog` is only a Dialog shell — wrap contents in `<Command>` or cmdk crashes.
- `CommandItem` appends an `ml-auto` check that takes space only on items setting `data-checked` (true or false), so a checkable list keeps its column and every other row runs to its edge. Right-aligned meta goes in `CommandShortcut` (which hides the check); row actions sit in flow after a `flex-1 min-w-0` text block, never absolute over padding. Items that can mount mid-search need an explicit `value`.
- cmdk reads arrows from keydown on its own root, so a `Command` popup without a `CommandInput` leaves focus on the trigger and the arrows dead: focus the root on mount (the runner's `PopoverCommand`). The kit root is `outline-none`, since a keyboard-opened popup would otherwise ring the whole list.
- A focusable control inside a `CommandItem` steals the keyboard's place — give it `tabIndex={-1}` + `preventDefault` on pointerdown, and refocus `CommandInput` in `onSelect`.
- cmdk 1.1.1 group filtering is broken (groups never reorder by score) — bypass with `shouldFilter={false}` plus own scoring via cmdk's `defaultFilter`.
- cmdk 1.1.1 loses its highlight when the highlighted item unmounts together with siblings (async results swapped in): every item's unregister check writes the same schedule slot, so the last one wins and nothing is selected — Enter goes dead. A list whose items come from a query controls `value`, falling back to the first option when the highlighted one is gone (`CellReference`).
- `PopoverContent` defaults to a padded `w-72` form box — menu-like popovers need the `padding` prop and usually `w-auto`.
- `DropdownMenuLabel` requires a `DropdownMenuGroup` parent (base-ui throws).
- base-ui `Menu.Item` closes the menu on click — in-menu toggles need `closeOnClick={false}`.
- base-ui `NavigationMenu.Link` does the opposite: it leaves the panel open on click, so a hash link scrolls its section under the still-open panel. Navbar links pass `closeOnClick`.
- base-ui render prop: `<Trigger render={<Button/>}>children</Trigger>` — children land inside. A non-button trigger needs `nativeButton={false}` + `aria-label`, and `<Button render={<a href/>}>` needs its own `aria-label` (jsx-a11y cannot see children through `render`).
- A `render={<Button/>}` wrapper that hard-codes surface classes makes the `variant` prop a lie — wrapper classes own position, animation and shape; the surface belongs to the variant.
- **Base UI writes orientation as `data-orientation="vertical|horizontal"`**, never a bare `data-vertical`. Tailwind compiles `data-vertical:` to a dead selector, so a vendored registry component must be rewritten to `data-[orientation=…]:` before use. Kit vertical separators size with `h-full`, so a fixed-height instance passes `h-4!`.
- **base-ui `Tabs.Panel` keeps an exiting panel mounted until `transitionend`** — with `transition-property: all` at `0s` it never fires and the old panel stays stacked under the new one. Render only the active panel.
- **A popup whose root mounts already-open never plays its entrance**: base-ui seeds `mounted` from `open`, so `data-starting-style` is skipped and only the exit animates. A `key` that remounts a component to reset its form does exactly this — the drawer/dialog root must sit **above** the keyed body. A body inside the portal also unmounts on close, which keeps its hotkeys from firing against a closed panel.
- Selects use macOS overlay mode (`alignItemWithTrigger`) + `min-w-(--anchor-width)`; never fix-width a trigger narrower than its longest option, and pass `size` to trigger *and* content.
- **Popups are opaque `bg-popover`, never glass.** A `backdrop-filter` on anything inside a base-ui floating `Positioner` renders unblurred in Chrome (it stays sharp with the positioner's transform, `will-change` and isolation all removed), so a `/70` popup just shows the dialog or rows behind it through its items. Glass stays for chrome that is not portaled through a positioner (the grid's bottom dock, toasts).
- **base-ui `Combobox` `items` must be a referentially stable array** — a layout effect pushes them into the store on every identity change, so an inline `data.map(...)` re-filters, rewrites refs and commits a second render per keystroke. Derive it where it can be memoized (a module-scope query `select`), and default the wrapper to a module-scope empty array.
- **A free-text field with suggestions is kit `Autocomplete`, never a `Combobox` with a controlled `inputValue`** — a single-select combobox resets its input to the selected item's label on close, so typed text (`varchar(255)`) vanishes on blur or Escape. `Autocomplete` is only a different root: every kit `Combobox*` part composes under it. A popup with no `ComboboxEmpty` hides itself when nothing matches.
- **`ComboboxTrigger` with an icon+label value needs its own flex wrapper** — `ComboboxValue`'s render function emits its children raw (no `data-slot` element), so an icon and a label become separate flex items of the `justify-between` trigger alongside the chevron, and the label drifts to the middle. Wrap the value in the span that lays it out (`selectTriggerVariants` only styles `select-value`, which `ComboboxValue` is not).
- **The combobox search input's ring suppression is `in-data-[slot=combobox-content]:ring-0!` (important) in `inputGroupVariants`** — the `focus-ring`/`invalid-ring` come from a `:has(…:focus-visible)` selector that outspecifies the `in-*` (`:where`, zero specificity) override, so without `!` the search field shows a stray focus/invalid ring inside the popup.
- **Never reset a dialog's or drawer's state where it closes** (submit success, Cancel, `onOpenChange(false)`) — the popup is still animating out, so the form visibly blanks mid-fade. Reset when opening, keep the state inside the content so the unmount clears it, or reset in the root's `onOpenChangeComplete(false)`.
- **Kit `Item` carries a transparent hairline border**, so a full-bleed row built on it sits 0.5px inside its container and `absolute` children resolve against the padding box. Full-bleed rows need `border-0`.
- **`FieldLabel` wrapping a `Field` is the registry's choice card** — that is what its `has-[>[data-slot=field]]:` rules are for, and how a whole row becomes one hit target without a click handler. Reach for it before building a row out of `Item`. It hovers on its hairline, not its fill: its surface is white in light theme on a near-white pane, so a tint mixes downward and reads as a hole.
- **Kit `Alert` is `w-full`**, so a horizontal margin pushes it past its container's edge by the margin. An alert inset with `mx-*` also takes `w-auto`.
- **A vertical kit `Field` stretches its direct children** (`*:w-full`), so anything else placed in one needs `w-fit` — `self-start` sets alignment, not width.
- **Kit `Field` and `FieldGroup` carry spacing as variants, not a base gap** (`Field` on `orientation`, `FieldGroup` on `size`) — one base gap cannot serve a label stacked over its control and one beside it. A call site dialing `gap-*` means the variant is wrong, not the value.
- **A dialog's submit button is outside its `<form>`** — `DialogFooter` is a sibling of the content, so `type="submit"` there submits nothing, silently. Every dialog form needs an `id` and its footer button the matching `form="<id>"`. `required` on a field whose submit is disabled while it is empty is dead too, and would preempt the house error UI if the disable were lifted — which is why `Form` sets `noValidate`.
- **A default dialog is a grid whose one column grows to its widest child's min-content**, and truncated text inside a flex row still counts at full width. A long name in a status line then widens the column past the dialog, and every child spills out of its edge. `DialogFooter` carries `min-w-0` for that; any other child holding a truncated value needs it too.
- **A field's error shows once its meta says `isBlurred`**: the only state a field re-renders on. Kit `useAppForm` marks every field blurred on a failed submit, so a never-blurred field (a custom control, a ⌘↩ submit from inside an input) still marks; a custom control forwards `onBlur` to `field.handleBlur` so it marks on leave like an input.
- **A router blocker sees a Back only after the browser has moved.** TanStack Router checks blockers for push and replace before they happen, but a back or forward only on `popstate`, so the address bar shows the previous page while the prompt is open and returns on Keep editing. Desktop has no address bar; on the web it is a library limitation, not something a call site fixes.
- **`<label for>` cannot name a `div`.** A select trigger is one, so a labelled select needs `aria-labelledby` pointing at an id on its label; a form field wrapper that renders a select wires that pair itself.
- **The invalid mark cannot sit inside another button** ([patterns.md](patterns.md)) — `FieldError` renders a button so the message is keyboard-reachable. A control that hosts it renders as a `div` (`SelectTrigger` passes `nativeButton={false}` + `render={<div />}`), so it styles `data-disabled:`, never `disabled:`.
- Base `Button` has an `active:translate-y-px` press dip that **replaces** any layout transform — never centre a button with `absolute` + `-translate-y-1/2`; use `inset-y-0 my-auto` or in-flow flex.
- `InputGroup` addon sizes direct-child svgs only — nested icons need an explicit `size-4`. `InputGroupButton` does not forward `size` to `Button` (it maps to its own cva), so every size in that cva must set its own icon-size rule or the icon silently falls back too big.
- A ghost icon button next to a filled input reads shorter than it is — they measure equal, but the field's fill, ring and shadow give it a lip the transparent button lacks. Fix by matching surfaces (`variant="outline"` + the field's radius), never by growing the button.
- **A `Button` variant with no rest text colour renders blue as a link** — the global `a { text-primary }` rule sits in `@layer base`, so any utility beats it, but only if one is there. `outline` carries `text-foreground`; `ghost` deliberately does not (its icon buttons inherit the row's muted colour), so a ghost button rendered as a link sets the colour at its call site.
- Router `Link` concatenates `activeProps.className` without tw-merge — use `data-[status=active]:` variants in one className.
- **sonner's `unstyled` drops the rule that hides a stacked toast's content**: a toast behind the front one is clamped to the front toast's height, and only `data-styled=true` fades its children out. The kit toast class carries that rule itself (`data-[expanded=false]:data-[front=false]:*:opacity-0`); without it a longer toast behind a shorter one spills its text out of its shrunken box.
- **A tooltip-wrapped button loses `data-slot="button"`**: `TooltipTrigger` stamps its own `data-slot` on the rendered element, so a `[data-slot=button]` selector misses every icon button with a tooltip. Match the `button` element instead.
- **An input-group button at either end sits the same distance from the group's side as from its top and bottom**: the inline addons offset their first or last button by the group height, the border width and the `--button-size` every kit button size sets once and derives its box from. A button that sets no `--button-size` (a raw `button` in an addon) sits flush against the edge, so a new button size or hand-built addon button sets it to its own height. That puts a trailing icon's centre half the control height from the right edge, and the `flat` select/combobox trigger pads its chevron to the same spot, so stacked form rows line their trailing icons up.
- Tooltip positioner is `pointer-events-none` (kit). Its entrance scales the popup up from the trigger, so an un-gated tooltip landing under the cursor makes the trigger see `mouseleave` and the hover flicker off and on.

## Focus, keyboard, input

- **`autoFocus` only covers the first render of a surface** — a row appended by a click or Enter mounts unfocused, and an input mounted by an interaction is not focused at all (activeElement stays `BODY`). Focus and select from a ref callback or an effect keyed on the flag that marked the row new.
- **A focus ring inside an `overflow-hidden` container is cut off** — `focus-ring` is an outer box-shadow, so a row in a clipped, rounded list (kit `Accordion`) shows nothing on focus. Draw it inside with `focus-visible:ring-inset`.
- **React Flow strips the focus outline off `.react-flow__node`** (its stylesheet sets `outline: none` on `:focus-visible`), and the focusable element is its wrapper, not the custom node. A card draws its own indicator keyed off that wrapper: `in-[[aria-roledescription=node]:focus-visible]:focus-ring`.
- **A form page opens with the first field the user must fill focused**, not the page or a select, so typing starts at once. A paste-first page is the exception: it opens on the page itself, since paste is its main entry and a focused empty field reads as a prompt to type; the page still holds focus so its shortcuts and paste reach it. Focus that field by its id (kit form fields take the field name as id), never a DOM query for "the first input": that matches the kit `Select`'s aria-hidden `<input>` and hidden file inputs, and skips textareas.
- Hotkeys: always `preventDefault()`; use `getOS(navigator.userAgent)` for ⌘ vs Ctrl labels.
- **A `target`-scoped hotkey hears every descendant** — buttons and checkboxes are not inputs, so `ignoreInputs` does not spare them, and the binding's `preventDefault` eats their Enter/Space. A container whose bindings belong to the container alone (the grid scroller) gates them on the container itself holding focus.
- **A popup that scrolls takes its initial focus on the scroller itself** (`tabIndex={-1}`), never a wrapper around it — arrows, Page Up/Down and Space scroll only the focused element's nearest scrolling ancestor, so a focused wrapper leaves a long popup unreachable from the keyboard.
- **Chrome makes an overflowing scroller a Tab stop when nothing inside it is tabbable.** A list whose rows are all `tabIndex={-1}` (the Navigator's, driven from its search) gives its scroller `tabIndex={-1}` too, or Tab lands on an unnamed box that only scrolls; the kit `ScrollArea` takes it through `viewportProps`.
- **A collapsed `ResizablePanel` keeps its content mounted** (`keepMounted`), so the kit marks it `inert`; without that, Tab walks into a hidden Navigator, chat or logger and typing lands in an invisible field.
- **A field that swaps its control on blur must not swap when focus moves to its own buttons.** Focus moves on mousedown, so the swap remounts the addon buttons before mouseup and the click lands on nothing. End editing only when the blur's `relatedTarget` is outside the field.
- **A control that unmounts itself on press drops focus to `body`** (a clear button that hides once the field empties, a rename input swapping back to its tab). Hand focus to the surviving element in the same task — `SearchInput`'s clear returns it to the field, the tab rename returns it to the tab.
- Every key a text field handles — Enter-to-submit, and arrows or Escape bound on it — must skip IME composition (`event.isComposing`; `nativeEvent` in React handlers), or CJK input submits half-composed and loses its candidate list. `@tanstack/react-hotkeys` does not skip it for you.
- Desktop kills text selection app-wide (`.electron body` `select-none`, opted back in by element type), so any component whose job is readable prose needs `select-text`. The `code`/`pre` opt-in excludes `button *` — code inside a click target would otherwise select a word on the second of two fast clicks. Repro in a browser by adding the `electron` class.

## Animation and layout

- **A bare `duration-*`/`ease-*` with no `transition-*` utility animates everything** — `transition-property` resolves to `all`, so the element transitions width, height and colour on any change, and base-ui holds a popup mounted for the duration on close. Durations belong with the animation they time.
- **tw-animate-css's `enter`/`exit` keyframes are overridden in the kit globals without `filter`.** Upstream animates `filter: blur(var(--tw-enter-blur, 0))` on every `animate-in`/`animate-out`, which keeps all of them off the compositor; so `blur-in-*`/`blur-out-*` do nothing here.
- **`animate-none` does not reliably cancel `animate-in`/`animate-out`** (Tailwind's own ordering wins) — make the animation classes conditional instead.
- **`AnimatePresence` only tracks its own direct children.** Rows returned by a wrapper component are one opaque child, so their `exit` never runs and they stay mounted forever. Render the array inline with keys, or keep such rows outside the presence tree.
- **`AnimatePresence initial={false}` also blocks mount animations deeper in that child's tree**, for as long as the presence parent doesn't re-render: a `key`-remounted `motion.*` inside it snaps to its final keyframe. Replay effects there (the guest banner's flash and shake) with `animate(ref.current, …)` from an effect.
- **A width-animated panel must have its content state ready on the opening frame** — mint the content's key synchronously in the interaction that opens it, never in a mount effect. Don't gate mounting on collection readiness; never block first paint on the network.
- **motion's `controls.set(label)` never reaches variant children** — every child keeps its `hidden` values, so a reduced-motion "show the finished picture" through `set` leaves it blank. Play the label instantly instead: `controls.start(label, { duration: 0 })`.
- **`Reorder.Group` values must be stable primitives** — it keys layout by `value` identity, so recreated objects re-measure everything and the strip twitches. Pass ids; set `axis` explicitly.
- `motion.create(X)` belongs in its own `x.motion.tsx`, never `x.utils.ts` — it creates an import cycle that throws a TDZ error. `.utils.ts` stays value-free.
- **A class or `data-*` change on a big container recalcs its entire subtree** (~90ms for the resource layout, sub-millisecond on a button; inline `style` edits on the same elements are <1ms). Animation gates, folding flags and settled markers on page-level panes must be inline styles or refs, never attributes a rule selects on. Small leaf elements can keep their `data-*` state.
- **Never clear a React-managed inline style to `''` imperatively** — React only patches keys whose prop value changed, so a width it set once and an effect later blanks stays blank forever. Restore the value React rendered, or pin through a property React does not own (`minWidth`/`maxWidth`).
- **Never `scrollIntoView`/bare `focus()` on mount inside a drawer, dialog or popover.** Both scroll every ancestor, `overflow-hidden` ones included, while the popup is still sliding in: the drawer jerks and the scroller's siblings (a `Command`'s search input) scroll out of view. Set the one scroller's `scrollTop` from the rects and focus with `preventScroll: true`.
- **A `lazy()` body inside a drawer swaps in mid-slide even when preloaded.** `lazy()` suspends on its first render regardless, and React keeps a shown fallback at least 300ms, which lands inside the 450ms entrance. Keep the preloaded component in a module variable and render it directly, with `lazy()` only for an open before the preload lands. Mark the component `'use no memo'`: the compiler treats the module read as constant and caches the first render's pick.
- **Raw error text (a TLS dump, a path, a token) wraps with `wrap-anywhere`, not `wrap-break-word`.** `break-word` does not lower the text's min-content width, so inside a grid track or flex item (the alert's `1fr` column) one long token still pushes the box past its parent; `anywhere` lets it shrink.
- A 1px line cannot be centred in an even gutter with whole-pixel padding — centre with layout, not padding.
- `content-visibility: auto` breaks a scroller's scroll math (skipped items measure as estimates) — use real virtualization.
- Scroll-edge fades must never cover the scrollbar: masks clip it and overlay siblings paint over it. `scroll-fade` (mask) only with `no-scrollbar`. A faded scroller whose children draw a hairline border (tab strip `border-b`) unions a 1px layer into `--scroll-fade-mask` with `mask-composite: add` (plus `-webkit-mask-composite: source-over`), else the line fades with the content.
- **A sticky header on the translucent canvas cannot hide rows with a fill** — `bg-body` carries the vibrancy alpha, so it stacks a second canvas layer and reads as a patch; and inside a `scroll-fade` scroller it fades with the content. Render it as an overlay sibling of the scroller and make the scroller's `--scroll-fade-mask` transparent for the header's height, restarting the top fade below it, and forward the overlay's `wheel` to the scroller (navigator tables list).
- **`scrollAnchor` pins a turn to the top and releases only when the answer fills the viewport**, so the same chat in two window heights un-pins at different moments and the scrolls drift apart. Its pass also fires on equal-count mutations and scrolls to the oldest unhandled anchor. The chat anchors nothing and lets provider `autoScroll` hold the bottom.

- **`dragConstraints` rescales drag offsets on resize.** motion keeps a dragged element's `x`/`y` proportional to its constraints box when the window resizes, so a start position stored in those motion values drifts (a full-page screenshot is enough to throw the cards out). Place the element with `left`/`top` and start `x`/`y` at 0; read both when drawing anything attached to it.

## Panes (`motion-panels`)

- Sizes are plain pixel numbers, so a pane resolves nothing against the group; `maxSize` is capped by what the other sized panes leave, so a pane can never push a sibling out.
- The package is outside the kit's Tailwind source globs — a className written *in* it produces no CSS. Styling belongs in the kit wrapper.
- **The separator must outrank pane content**: it is a sibling of the panes, so at equal `z-index` the later pane's sticky chrome paints over the drag line. The kit separator sits above every in-pane sticky layer and below floating popups.
- **Only the outermost group clips.** A sized pane keeps its pixel size, so a too-narrow window would spill the panes into document overflow — the root group takes `overflow: clip` (not `hidden`, which scrolls). A nested group must stay `visible` or it cuts what its card paints at its own edge. `overflow-clip-margin` is not the fix: the margin becomes scrollable overflow again.

## Data, storage, tables

- Opaque cells (pinned columns) paint over their row's background, so they repeat the row's hover as `group-hover/row:bg-accent`.
- **seitu `createWebStorageValue.set` is synchronous per call** — stringify, `setItem`, then a synthetic `StorageEvent` that wakes every persisted value on the page. Never call it per frame; a per-frame value lives in component state and persists through a `debounce`.
- **seitu `useSubscription` defaults to `deepEqual`** — a selector returning a fresh array or carrying query results deep-compares all of it on every store change. Pass `isEqual: Object.is` and let the store hand out a new reference.
- `@tamery/table`'s `renderCell`/`renderHeader` are called, never rendered as components — `<Cell/>` from a render prop remounts the cell subtree on every parent render and kills local cell state. Cells receive their geometry as a `style` built from the grid's per-column variables; spread it as-is.
- **An inherited custom property written while scrolling restyles every descendant**. Per-scroll geometry is either set on the leaf that reads it or registered `inherits: false` with `@property` (`globals.css`) and set on the element whose class reads it.
- **Grid rows, cells, headers and documents are `memo` boundaries** fed only stable props, so a range change renders just what it mounts. A prop rebuilt each render (an inline `rangeExtractor`, a `labels` Map from an inline `useQueries` `combine`, an uncompiled hook's `cursor`) silently re-renders every visible cell; check with a commit-hook render count before and after.
- **Every grid header is its own stacking context** (the drag shift is a `translate`), so a child's `z-index` cannot rise above the next header: anything a header hangs past its right edge is covered and a press there lands on the neighbour.
- **A custom property name set through `style.setProperty` is taken literally, while `var()` unescapes its argument** — a `CSS.escape`d column id never matches its own variable. The grid encodes ids into plain idents instead.
- **A table skeleton must pin the same column widths the data will get.** In an auto-layout table, percentage bars resolve against a column still being computed and contribute nothing, so the loading table sizes columns from header text and reflows on arrival. Size skeleton bars in `ch` and give skeleton cells the real cells' width classes; a skeleton over explicit pixel columns is already stable and may use percentages.

## Code rendering (streamdown, shiki, Monaco)

- Streamdown needs `@source "../../node_modules/streamdown/dist/*.js"` in globals or it renders unstyled. Its `pre` renders no element (it only stamps `data-block` on the code child), so `ResponseCodeBlock` takes over through `components.code` — branch on `'data-block' in props`, and drop the `node` prop before spreading onto an inline `<code>`.
- **Streamdown ships its own block spacing** (`li` padding, heading margins), so kit prose margins stack on top and chat reads twice as airy as authored. `Response`'s prose string must *replace* them, and its `list-inside` lists need `list-outside` with a margin. Check the dist defaults before adding a margin.
- `@streamdown/code`'s `highlight` schedules a tokenization on every cache miss and queues a callback per call, so `CodeBlock` calls it from the store's `subscribe` alone and serves `getSnapshot` from a per-instance cache. Calling it from `getSnapshot` tokenizes three or four times per render.
- Shiki's dark theme needs the one `!important` rule in globals (the light colour ships inline), or dark mode renders github-light and identifiers go invisible. Keep `data-slot="code-block"` on anything that should get it.
- **Monaco SQL takes its language id from `sqlLanguageIds`, never `"sql"`** — the four dialect languages are registered in `@tamery/monaco/sql-language` (tokens from `@tamery/sql`, completion and diagnostics bound per model); a `sql` model gets stock grammar and nothing else. Its themes are hand-mapped from shiki's palettes so editor and `CodeBlock` read as one — keep the two in step.
- **Monaco view zones render in a detached React root** — no context of any kind crosses (router, query client, stores). Zone components take everything as props or module-level stores; swapping a prop for a context hook typechecks, then throws at mount. The gutter layer paints over anything a zone draws left of the content column, so a zone's card is inset far enough for its shadow, and the zone is taller than the card.
- **Monaco marks every view zone `aria-hidden`**, so a control inside one is invisible to screen readers. Anything interactive goes in an overlay widget that follows an empty zone's `onDomNodeTop` (Monaco's own zone widgets do this); the zone only makes room.
- **An editor with an inline-completions (AI ghost text) provider must set `quickSuggestions.other: 'on'`.** Monaco 0.56 defaults it to `offWhenInlineCompletions`, which holds the suggestion list until the ghost-text provider answers — a network round trip per keystroke that reads as laggy autocomplete.
- **With the suggestion list open, Monaco re-asks the ghost-text provider on every row move and shows only ghost text that extends the focused row.** Ghost text asked for with a row focused lands in a separate slot and draws only when it starts with that row's text, so the SQL provider draws it itself as an injected `ghost-text-decoration` (first line only), and the accept/dismiss controls call `acceptGhostText`/`dismissGhostText` instead of Monaco's inline-suggest commands. It asks the AI once per text version while a row is focused, never per arrow key. `inlineSuggest.experimental.showOnSuggestConflict: 'always'` keeps ghost text that was already shown. `suggest.preview` stays off: the row preview uses the ghost-text classes and reads as an AI suggestion.
- **Tab over ghost text with the suggestion list open never reaches `inlineSuggest.commit`** — its keybinding requires the list closed. A list with a focused row inserts that row, and a list opened by a trigger character (no focused row) lets Tab indent. The SQL editor intercepts Tab on key-down whenever the list is visible and its ghost text is live.
- **Kit controls inside the editor (view zones, injected buttons) get Monaco's square focus outline**: its stylesheet outlines every focused `button`, `input`, `textarea` and `[tabindex]` under `.monaco-editor` with a selector that beats `outline-none`. Our themes set `focusBorder` transparent, so the kit's own focus styles are the only ones.
- **Never use Monaco's own hover widgets** (`glyphMarginHoverMessage`, marker hovers are fine): they render in Monaco's stock chrome, not the kit's.
- **Marker hovers wear the kit tooltip** (`monaco.css`): inverted fill, `text-xs` sans, no status bar, no copy button (the text is selectable). Recolour through Monaco's `--vscode-*` vars, never the properties — its stylesheet is injected after ours. Font needs `!important`: Monaco stamps the editor's mono font inline on the hover and every marker.
- **A rounded Monaco box never clips with `overflow-hidden`.** The suggest list sizes itself against the window and overflows the editor, so the container's clip cuts it off; `monaco.css` makes the editor inherit the container's radius and clip its own text. A ring + `rounded-*` on the wrapper is enough.

## Platform

- Electron `Menu.popup`'s item `click` can fire *after* the close callback — resolve on click immediately and settle null on a short delay. The platform branch lives in `AppContextMenu` in `apps/app`; `packages/ui` stays electron-agnostic.
- **Chrome's autofill paints the `input`, not the control around it** — a transparent input inside a rounded filled `InputGroup` draws a blue rectangle breaking out of the rounding. Kit `Input` neutralises it with an `autofill:shadow-*` inset fill plus `-webkit-text-fill-color`. It must be the `shadow-*` utility, never an arbitrary `[box-shadow:…]`: Tailwind composes rings into `box-shadow`, so setting the property outright erases the focus and invalid rings. The fill is a rectangle unless the input is rounded too, so `InputGroupInput` inherits the group's radius — a square input paints its corners over the group's ring.
- A trigger rendered as a `<div>` (`nativeButton={false}`, e.g. `SelectTrigger`) shows the I-beam over its text and lets it be selected; a `<button>` gets the arrow cursor and no text selection for free, so such a trigger carries `cursor-default select-none` itself.
- A kit `PopoverContent` mounts a render after the component that renders it (base-ui creates the portal node in an effect), so an owner's `useHotkeys` targeting a `useRef` to the popup binds nothing. Hold the popup in state (`ref={setPopup}`) and pass no hotkeys until it exists (`popup ? [...] : []`), not `enabled: !!popup`: a disabled binding still registers, a `null` target falls back to `document`, and two bindings of one key on one target warn "already registered" even when one is disabled. The same applies to a dialog shortcut that mirrors a page shortcut — bind it to the dialog popup, not `document`.
- **Overlays are their own view-transition groups.** Tab content sits in motion's `AnimateView` (a React `<ViewTransition>`), so any transition or Suspense reveal inside a tab — including one inside a portaled drawer — makes React start a document view transition, and its named tab group paints above every overlay. `globals.css` names each `[data-base-ui-portal]` child (`match-element`, class `overlay`) with no animation and no old snapshot, so overlays stay live on top. A portal not rendered by Base UI needs the same treatment.
- **`LoadingContent` lays its children out as a flex row with `gap-2`.** A label that mixes text and an element (`Save (<NumberFlow />)`) splits into spaced-out items — wrap the label in one `<span>`.
- **A popover anchored to a virtualized grid cell closes when the grid scrolls.** Virtualization unmounts the anchor and the popup jumps to the viewport corner. Keep one popover per grid in state (`{ anchor, … } | null`) rather than one per cell, and drop it on the scroller's `scroll`, as the reference peek does.
- **A tooltip's content must not change while it animates out.** Its popup stays mounted through the exit animation, so content keyed to a live flag (the ⌘ reveal) re-renders mid-fade and flashes. Latch the open-time state and clear it in `onOpenChangeComplete(false)`, as the kit `Tooltip`'s `shortcut` mode does.
- **A flex `<fieldset>` ignores `min-height` for alignment.** Kit `Field` renders a `<fieldset>`; Chrome sizes its anonymous content box to the content, so `min-h-*` plus `items-center` leaves a short child (a label beside a `Switch`) pinned to the top. Height a row from its children (the `row` orientation gives the label `min-h-8 items-center`), never from `min-h` on the field.
- **`InputGroup variant="flat"` rounds by position** (`first:rounded-t-xl last:rounded-b-xl`): it is for a field stacked at the top or bottom of a popup card (cell editor, seed panel). In a row beside a label or another control it is neither first nor last, so its focus ring draws square corners while a lone sibling's draws round ones. Rows take `variant="inset"`, which is always `rounded-xl`.
- **A `Select` popup lays its selected item over the trigger** (`alignItemWithTrigger`), lining up `ItemText` with `select-value`, so the two need the same inner layout (`items-center`, the same gap per size) or an icon in the value jumps when the popup opens. Change one, change the other.
- **A CSS mask clips everything to its element's box, shadows included.** Fading a group of shadowed surfaces (`mask-b-from-*` on the agents demo) cuts their shadows into a hard vertical edge at the box's sides. Put the mask on a wrapper that reaches past the shadows (`-mx-20 px-20`); the marketing layout root is `overflow-x-clip`, so the overhang never scrolls the page. The same goes for anything that moves inside a masked box: a `ProductCrop` window lifts on hover, so its masked box keeps padding above the window to lift into, or the lift cuts off its top edge.
- **A scroll container clips a row's outer ring.** The Navigator lists' `SidebarContent` pads its top and right edges by 2px and pulls them back with negative margins, so the active row's highlight ring fits without moving any row; keep that pair if the padding changes.
- **`NumberFlow` pads its box with a fade mask** (`--number-flow-mask-height`, 0.25em above and below), so it never lines up with plain text set at the same size beside it. Zero the variable on an instance that must align with a sibling element, and give the plain text `leading-none` to match.
- **A virtualized grid rendered on the server draws no rows** — the virtualizer sizes its window from the measured scroll element, which does not exist until hydration, so a streamed page shows an empty box (neither rows nor its skeleton) until the client measures. The kit `Grid` passes TanStack Virtual's `initialRect`, so the server renders the first screen of rows and the client's first render matches it. Column widths are CSS variables the client sets after mount, so every `var()` that reads one carries the column's size as its fallback, or server-rendered cells shrink to their text.
