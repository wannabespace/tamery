# Improvements

Backlog of product improvements, ranked by uniqueness vs effort. **Every future improvement idea goes in this file** — append it to the matching section (or a new one) instead of leaving it in chat, a PR description, or a scratch doc. Remove an entry when it ships or gets rejected.

Suggested order: 5 → 1 → 3 → 2. Schema notes improve every AI feature at once, the agent reuses drafts, impact preview makes the agent safe, and MCP exposes the same safe tools to outside agents.

## Ranked

1. **Agent chat where every AI write is a reviewable draft.** The chat (`packages/ai/features/chat-stream.ts`) gets no schema and no tools today. Add tools — `listTables`, `describeTable`, `runReadOnly` (row-capped, through the client proxy) and `proposeChange`. `proposeChange` writes into the existing table/visualizer drafts and review drawer, so the AI never writes to the database directly; the user approves a diff. Tools are schema-only in `packages/ai` (no `execute`) and run in the renderer, where connections live: MCP's implementations (`modules/mcp/describe-table.ts`, the `tables`/`query` methods in `mcp-source.ts`, `fetchForAgent`) move to `core/agent/` taking a resolved `connectionResource`, with `modules/mcp` and `modules/chat` each a thin adapter (target resolution, error hints, events).
2. **MCP beyond the desktop server.**
   - `tamery mcp` in the CLI for web-only users (needs a CLI sign-in + `cli query`).
   - More per-connection policy: row limit, masked columns.
   - A server-side row cap: on Postgres, MySQL and SQL Server the 200-row cap bounds memory but not transfer — the server still sends every row over the app's only pooled connection. SQL Server's `SET ROWCOUNT` would also cap `execute`'s writes and MySQL's `SQL_SELECT_LIMIT` is session state, so Postgres needs a cursor and the others a reset that cannot be skipped.
   - With no signed-in window open, main could open one instead of answering "Open Tamery and sign in first.".
   - Tools that act on Tamery itself — rename a connection, open a table or query in a tab for the user. Asked to rename a connection today, an agent has no tool for it.
   - A Settings switch (or an approval) for agent-created connections: today nothing stops an agent adding one — even one steered by text in the rows it read — and each attempt test-connects to whatever host and port it names; the connection always starts at Ask before writing.
   - `query` is read-only and always rolled back, so it could retry once on a dropped connection like typed catalog reads do; today the first query after a server closes an idle connection fails with "Connection lost".
   - Row estimates beyond Postgres and MySQL: SQL Server's `SHOWPLAN_XML` `EstimateRows`, ClickHouse's `EXPLAIN ESTIMATE` for the `SELECT` a mutation filters on.
   - The Dock's "Running in Background" label. macOS 27 shows it only once the main process quits and a registered helper (an `SMAppService` agent, which brings the one-time Background Items prompt) keeps going, so it needs the server hosted outside the renderer.
   - A token per client: every client shares one token, so **Connected clients** trusts the name each reports and none can be cut off alone. Per-client tokens make the list trustworthy and revocable, at the cost of a different config per client.
3. **Impact preview before a destructive run.** The runner, and MCP's Ask before writing, could try an `UPDATE`/`DELETE` in a transaction that rolls back, show the changed rows, and require it on connections marked as prod. Only an allowlist is safe to try: one plain DML statement with no transaction-control, `INTO`, `COPY` or procedure word, since a SQL Server batch can `COMMIT` mid-statement and some statements act outside the transaction.
4. **Undo for applied changes.** Store inverse statements when a draft is applied; offer "Undo last apply" in the query logger.
5. **Schema notes (semantic layer).** Per-table and per-column descriptions ("status 3 = refunded", "amounts in cents"), AI-drafted, user-edited, synced per workspace. Added to every AI prompt so filters, completion and chat all get more accurate.
6. **Explain plan plus "why is this slow".** Visual plan for slow queries (already detected); AI suggests an index that lands as a visualizer draft.
7. **Schema diff between connections** (e.g. staging vs prod). Output a migration in SQL, Drizzle or Prisma, reusing codegen.
   - **Copy database beyond PostgreSQL.** Postgres ships (`pg_dump | psql` in the desktop database process). Left: MySQL and MariaDB through `mysqldump`, which also needs bundling; copying into a database that does not exist yet (typed in the target picker, created first); table sizes in the list, as TablePlus shows; a subset that brings the enums and functions its tables use, which `pg_dump --table` leaves out, so a fresh target fails on them today; a step bar (connect, dump, restore) over the raw log; scheduled copies; client keys protected by a passphrase (`sslpassword`), which libpq reads only from a connection string or a service file, so the copy would need the passphrase in argv or on disk; a dropped network still leaves pg_dump's locks and snapshot on the source until its server notices (pg_dump runs no SQL of ours, and the startup `options` parameter breaks PgBouncer), and a target behind an SSH bastion keeps its transaction until the bastion's sshd notices the dead session; a dump stalled with data in flight hangs on TCP retransmission rather than keepalive, since `tcp_user_timeout` is Linux-only, so Stop is the way out.
8. **Auto-charts on results.** Pick a chart from result shape (time + number = line, category + number = bar). Toggle in the results pane, no chart builder.
9. **PII masking.** Mark columns sensitive; their values are masked before anything reaches the model or MCP. Build together with 2.

## Deferred

- **Notebooks / dashboards** — a different product; saved queries plus auto-charts cover most of it.
- **More engines** (Mongo icon exists) — no differentiation, each costs dialect work. `toMongoPipeline` already runs filters through a reference (`via`), but Mongo has no foreign keys to offer the targets: references would have to be inferred (ObjectId fields found in another collection) or declared by the user.
- **Team features** — blocked until multi-member workspaces exist.

## Table

- **Name the ClickHouse error when a read fails mid-stream.** A table whose rows no longer fit its column type (an enum value dropped outside Tamery) fails every read, but ClickHouse has already sent HTTP 200, so the client rejects with a bare `aborted` and the grid's error view says nothing useful; one QA pass on an older server even showed `This table is empty.` The column form now refuses dropping a value rows still hold.
- **Column form gaps.** MySQL `SET` columns could take the same values list as `enum`; **References** always writes `NO ACTION` for ON DELETE / ON UPDATE and only on a column without a foreign key, so changing or dropping a column's reference still means the Schema page or the visualizer; ClickHouse lists enum values by their stored number, so dragging them in the list changes nothing and the grip could hide there. The visualizer applies one statement per draft, so renaming a MySQL enum value there is still refused in strict mode; the table grid's form moves the rows.
- **New visualizer tables land on top of others.** **+ Table** places the node at the viewport centre whatever is there. Moving it clear of the cards it covers can push it off screen, and panning to it is computed before the inspector opens and narrows the canvas, so it needs the pane's size after that render.
- **Hold-⌘ hints for shortcuts without a control.** Tooltips with a shortcut reveal on ⌘; undo/redo (⌘Z/⇧⌘Z), the grid's copy/paste/fill (⌘C/⌘V/⌘D, listed only in the cell menu) and the Schema pages' ⌘D drop have no control to carry a hint, so they stay undiscoverable until something on screen names them.
- **Esc hints on dialog and drawer closes.** Every `Cancel`/`Close` that Esc fires (dialogs, drawers, the seed panel) carries no hint while ⌘ is held; a kit-level `shortcut` on the close components would cover all of them at once. The editable list's reorder keys (`⌥↑ ⌥↓`) are still unicode in its tooltip text rather than a `shortcut` glyph.
- **Referenced columns on the columns context.** Each header still calls `useReferencedColumns` for its own column; the fetch is shared through the query cache, but one lookup on `ColumnsContext` would drop the per-header hook.
- **Readable rows in the delete dialog.** It lists primary keys only (UUIDs); showing the row's label column (the one **Show Labels** picks) beside each key makes it clear which rows are going.
- **Keep staged edits across a reload.** A page reload drops every staged cell edit and new row without a prompt; persist drafts per table, or at least confirm before unload while any are staged.
- **Drop and change type from the column menu.** The grid can add and rename a column but not drop it or change its type; both need the query runner today.
- **Default value in Add column.** The dialog offers name, type, nullability and array only, so on Postgres and SQL Server a `NOT NULL` column cannot be added to a table that has rows (the engine has nothing to fill them with), and a default needs SQL.
- **Sort from the cell cursor.** A header click cycles its column's sort, but from the keyboard the only route is the column menu; a grid hotkey cycling the cursor's column (⇧ to add it to the sort) would match the click.
- **Sort in Code → Query.** The generated SQL, Kysely, Drizzle and Prisma queries carry the table's filters but not its sort.
- **Faithful dialect types and defaults in schema copy.** ClickHouse SQL copy must omit an empty default expression; MySQL `SET` columns must preserve multiple-value semantics in ORM output or clearly disclose that the format cannot represent them.
- **Lossless custom indexes and composite foreign keys in Code → Schema.** Postgres copies a custom index from `pg_get_indexdef`, but MySQL (prefix length, descending, functional) and SQL Server (filtered, included columns, descending) custom indexes still come out as plain column lists, and a multi-column foreign key is emitted as one key per column.
- **SQL Server `bit` as a checkbox.** Only Postgres `boolean` gets the boolean editor; a `bit` cell is free text, so `t`/`f` fails at Save. MySQL's `bit(n)` is a bit field, not a boolean, so the mapping has to be per engine.
- **Stable row order without a sort.** An unsorted grid follows the database's physical order, so a saved row jumps from the top to the bottom, and offset paging without `ORDER BY` can repeat or skip rows between pages. Ordering by the primary key fixes both, but the key comes from the constraints query, which the tab-open prefetch does not wait for — the prefetched first page would sit under a different query key.
- **Say when a filter or sort change drops staged edits.** The save bar just disappears; a toast with an Undo action would make the ⌘Z recovery discoverable.
- **Horizontal scroll re-renders every visible row.** A column-range change hands each memoized `Row` a new `virtualColumns`, so all ~45 rows re-render and re-lay out (~40% of a horizontal step). Positioning cells per column (one spacer per row read from a CSS variable) would let a range change touch only the columns that enter and leave.
- **Keep `GridScroller` chrome out of range renders.** Every row or column range change re-renders the body's `AppContextMenu` wrapper (~2ms in dev) because its child element is new each render.
- **Edit a view's query.** Views can be created, renamed and dropped from the navigator, but changing what one selects still needs the query runner (`CREATE OR REPLACE VIEW`, or drop and recreate for a materialized view).
- **Refresh a materialized view.** Postgres materialized views only change on `REFRESH MATERIALIZED VIEW`; a menu item on the view's row (with `CONCURRENTLY` when it has a unique index) would keep its tab from showing stale rows.
- **SQL Server indexed views.** SQL Server's equivalent of a materialized view is a `SCHEMABINDING` view with a unique clustered index, so New View offers no Materialized option there yet.
- **Structured document editor for MongoDB.** Insert document is a free-form mongosh/Extended JSON editor (highlighted, with catalog completion); a field-by-field view like Compass's — each row a key, a type picker and a value, nesting into sub-documents and arrays — would let someone build a document without knowing BSON syntax, and edit an existing document the same way the grid edits a cell.
- **Frame the Insert document editor's AI ghost text as an insert.** The editor holds a bare `{ … }`, so the ghost-text prefix sent to the model is an object literal, not a `db.<collection>.insertOne(…)` call; the mongosh completion prompt expects a db call, so wrapping the context (as the static completion already does) would give the model the collection and the insert intent and sharpen its suggestions there. The Query runner has the full call, so it is unaffected.
- **A custom seed value for MongoDB.** The seed panel's SQL-expression generator is SQL-only because it emits `sql.raw` the database evaluates per row, and MongoDB seeds `insertMany` literal documents the browser builds, so there is no server-side expression. A MongoDB generator could still take a constant relaxed Extended JSON value (`{"$oid":"…"}`, a fixed sub-document) parsed client-side and inserted into every row; a per-row `ObjectId()`/`new Date()` form would need the shell-BSON parser on the client (it is node-only today) or routing seed values through the executor.
- **Richer MongoDB indexes.** The Add index form covers ascending compound keys with unique, sparse and TTL. A per-field direction picker (`-1`), the special key types (`text`, `2dsphere`, `hashed`), a partial-index filter, and collation would cover the rest of `createIndex`. A **Search Index** (Atlas Search) is a separate object — a JSON mapping definition against `$search`, available only on Atlas — so it needs its own form, as Compass splits them.

## Query runner

- **Show an open transaction on its tab.** Commit and Rollback appear only in the runner's toolbar, so a transaction left open in a background tab is invisible until that tab is opened again; a dot on the tab (and a confirm before closing it, rather than the rollback toast after) would keep forgotten transactions from holding locks for the 15-minute idle timeout.
- **End a reloaded web tab's transactions at once.** On the web nothing rolls back a transaction whose tab reloaded: the proxy holds its session, and its locks, until the 15-minute idle timeout. Rolling back the `txId`s the runner keeps in sessionStorage on the next load (or a `pagehide` beacon) would free them right away.
- **Keep a window's transactions when another reloads.** The desktop main process rolls back every open transaction when any window navigates (`resetTransactions` in `main.ts`), so reloading one window ends a transaction another window holds. Owning transactions per `webContents` (`ownerId` from the IPC event) would scope the reset to the window that reloaded.

## Offline writes

- **Show and unstick the outbox.** Writes replay in order and the executor retries any 5xx or network error forever, so one write a server bug keeps rejecting holds every later one, and web connection creation (which waits for its write) spins until it lands. Nothing on screen says writes are pending; a pending count plus a way to discard a stuck write would make that recoverable without signing out.
- **Offline writes from every tab.** Only the tab holding the executor's leader lock queues writes; another tab falls back to a plain transaction that rolls back when offline after the save toast already showed. Forwarding non-leader writes to the leader (or failing them up front with a clear message) would close the gap.
- **Move to TanStack DB 0.15.** `@tanstack/react-db`, the SQLite persistence packages and `offline-transactions` are pinned to the `@tanstack/db` 0.8 line. 0.15 drops `begin({ immediate })`, and a synced commit there always waits for every persisting transaction, which is the case `writeSynced` in `apps/app/src/lib/sync.ts` works around (a synced row would vanish while a later outbox write is pending). Moving up needs a new way to land a server-confirmed row while the outbox is busy, then the four packages bump together.

## Sign-in

- **New backup codes from Settings.** Backup codes are shown once, when 2FA turns on; someone who lost them or used them up has to turn 2FA off and on again. A "Regenerate backup codes" action (`twoFactor.generateBackupCodes`) would cover it.
- **Track web auth actions.** `apps/main` has no PostHog, so sign-in, code and two-factor actions on the web are invisible; only the desktop's `signed_in`/`signed_up` after the exchange is captured.

## Connections

- **Say why a connection row won't open.** The row is clickable only through its overlay link, which renders only when the selected resource is in the synced resources collection and the connection can be queried (`connection-card.tsx`). Otherwise a click does nothing and nothing is shown — no hover, no reason. The row could fall back to opening the connection or show a tooltip saying why it can't.

- **More connection types on borrowed dialects**, added the way `dialects.md` describes for MariaDB. Candidates by fit:
  - Name only: Percona Server and Dolt (MySQL), Azure SQL Database (SQL Server).
  - Name plus capability gates: CockroachDB (partial `pg_catalog`, no extensions, domains or table inheritance, limited `ALTER COLUMN TYPE`), YugabyteDB (reuses Postgres's query layer, near identical), Aurora DSQL (no foreign keys, triggers or extensions), TiDB (no triggers, procedures or events).
  - Own dialect over a borrowed protocol: Redshift, Greenplum, Materialize, RisingWave, QuestDB, CrateDB, SingleStore, StarRocks, Doris, Babelfish, Fabric Warehouse.
  - Not connection types: Neon, Supabase, RDS, Aurora, AlloyDB, PlanetScale and ClickHouse Cloud are hosts (`hosts.ts`); TimescaleDB, Citus and pgvector are Postgres extensions.

  The first type that lacks something its dialect offers moves the capability gates (about 120 calls) to its type. Check each candidate's limits on a live server first: they shift between releases.

- **Pin the cloud proxy's resolved address.** `assertReachable` resolves the host, then the driver resolves it again, so a DNS answer that changes between the two (rebinding) still reaches a private address. Passing the checked IP to each driver (pg `host` plus `ssl.servername`, mysql2 `host`, tedious `server` plus `serverName`, a `lookup` on the ClickHouse agent) closes it.
- **Refuse redirects from a libSQL server on the cloud proxy.** `@libsql/hrana-client` fetches with the default `redirect: 'follow'`, so a public libSQL host could send the proxy on to an internal URL the host check never saw.

- **Hosted Postgres and MySQL as providers.** Turso and Cloudflare D1 are providers (`Provider`); Supabase, Neon, PlanetScale, ClickHouse Cloud and the rest of `HOST_HINTS` (`hosts.ts`) could join them, so the Engine select offers them with their own placeholders and the list shows their marks. Their host suffixes change, so the form saves the provider the user picked, and a paste only guesses it from `HOST_HINTS`; a suffix the list lacks leaves the plain type until it is added.

## Settings

- **One home for the theme.** Theme now lives in Settings → Appearance and still in the avatar menu; keep one once it is clear which people use.
- **Sync preferences to the account.** Theme and shortcut reveal are per device (localStorage), and Clear cache resets them. Syncing them would carry the choice to a new machine.
- **Settings… in the native app menu.** Mac users look for ⌘, under the Tamery menu, but only the avatar menu and the in-page hotkey open Settings. Needs a menu item plus a main-to-renderer navigate event.
- **Re-check ⌘ hints while ⌘ is held.** A hint hit-tests its control once, when the reveal starts, so a control uncovered mid-hold (a menu closed) shows no hint until ⌘ is pressed again.
- **Start at login on Linux.** Electron's login item is a no-op there, so the row is hidden; an XDG autostart `.desktop` file would cover it.
- **Ask for browser notification permission from a gesture.** The web build asks on the first notification, which Safari ignores outside a user gesture and which reaches every other browser while the user is away. A Settings → Notifications switch (or the first chat send) could ask instead, and let the user turn notifications off.

## SSH tunnels

- **Honor more of `~/.ssh/config`.** `UserKnownHostsFile` and `StrictHostKeyChecking` are ignored and a `ProxyJump` host is refused: host keys always go to `~/.ssh/known_hosts`, a new key always asks, and a bastion behind another bastion can't be reached.
- **Docker beyond Linux bridge networks.** A container host resolves to its bridge address, which only the SSH host's own network stack reaches: rootless Docker, a container on `network_mode: host`, and Docker Desktop on the user's own Mac need another route (`docker exec` into a relay, or the published port).

## Connection form

- **Read a paste at once in a SQLite file or D1 database ID field.** A pasted connection is read immediately only in the Host field; on SQLite and D1 the main field is the database one, so a pasted D1 dashboard link or `sqlite://` string is read only on blur. Comparing the paste target with the engine's main field would make every engine behave the same.
- **A local model for pastes the parsers don't read.** When `guessConnection` finds nothing, the app could hand the text to a small model running on the device (desktop, or the browser through WebGPU/WASM, as in-browser extractors already do) to pull out host, port, user and database from the long tail (compose files, Kubernetes secrets, a wiki paragraph), then show the result through the same fixes, footnote and focus as a parsed paste. Only as a fallback: the text holds secrets, so it never goes to the cloud, and a model can garble a password, so the parsers keep everything they recognise. An extractive span model (GLiNER-style, through transformers.js or ONNX Runtime Web) fits best, since it can only point at text, never invent a value; a generative one would need every value checked verbatim against the input. Weights load on the first paste that needs them, never on page open. Start with a prototype over 20 to 30 real pastes, recording per field found, missed or wrong, plus load and inference time in Chrome and Safari.
- **Ask for a password the server turns out to need.** A connection saved without a password (Save goes through after a failed test) that the server then rejects for it only shows the diagnosis on the card; the connection's form opens for a missing password only when `isPasswordExists`. Opening it on that auth failure too, and setting `isPasswordExists` on save, would recover it without a trip to Edit.
- **An SSL control per engine.** SSL today is typed into Options (`sslmode=require`, `encrypt=true`, `ssl=true`). A switch whose meaning comes from `capabilities.ts` would save users from learning each driver's parameter.
- **Offer the clipboard on open.** The form only reads what is pasted; the desktop app could read the clipboard on open without a prompt and, when it holds something `guessConnection` recognises, offer to fill the form from it.
- **SSH through `tamery proxy`.** The local proxy runs on the user's machine, like the desktop app, so it could open tunnels too and make SSH connections usable from the web app.
- **Diagnose from the server's side too.** The failure rules read only the driver's message; a TCP probe of the port (open, closed, filtered) and a DNS check for IPv4/IPv6 records, run on the device before the driver, would tell "nothing listening" from "firewalled" from "IPv6-only" without guessing from the error text.
- **Retest after an SSH fix.** Turning the tunnel on from the failure alert stops at focusing SSH Host; once the bastion host is filled in, the test could rerun on its own.
- **Hide found databases that are already saved.** The create page lists every database it finds on the machine, including ones the user added last week. Matching each against saved connections the way a connection link does (engine, host, port, user) would leave only what is new, and the list could disappear once everything is in.
- **Bring DBeaver's SSH tunnel along.** Found TablePlus connections carry their SSH host, but DBeaver keeps its tunnel in a handler block of `data-sources.json` that the reader skips, so a DBeaver database behind a bastion arrives without its tunnel.
- **Test as you go, then pick the database.** A debounced background test once host and credentials are filled would turn the footer into a live status ("Connected · PostgreSQL 16.4 · 12 ms") and drop the separate Test step; once it connects, Database becomes a combobox of the server's real databases instead of a free-text guess.
- **Mark production at creation.** A host or database containing `prod` (or a provider's production branch) could preselect a red color and a "Production" label, and offer read-only or ask-before-writing access there, so the safety decision happens before the first query instead of after the first mistake.
- **Add every database in a pasted `.env`.** A `.env` often holds several (`DATABASE_URL`, `ANALYTICS_DATABASE_URL`, `SHADOW_DATABASE_URL`); the parser takes the first. Listing all of them with a checkbox each would add a project's databases in one paste, named from their variable.
- **Open in Tamery links beyond the desktop.** The desktop app opens `postgres://`, `mysql://` and the other database schemes, but a browser can register only `web+` schemes, so the web app gets none. A `tamery://connect?url=…` link (and `tamery add <url>` in the CLI) would reach both.
- **Fill the password from a matching link.** A database link that matches a saved connection opens it as is; when the saved string has no password and the link carries one, offering to store it would skip the password form.
- **Secrets from a password manager.** Accept `op://vault/item/password` (1Password) and Keychain references in the password field, resolved at connect time, so a synced connection string never holds the secret itself.
- **A bare host pasted on a SQLite engine moves to a server.** With SQLite, Turso or D1 chosen, a paste that names only a host with no telling port (`db.example.com`) names no engine, so it stays on that engine and fills nothing visible. A host with no scheme is almost never a SQLite location, so the form could switch to a server engine.

## Desktop app

- **Find local databases off the main thread.** The first `localDatabases.find` loads the finders and the keyring addon in main and stalls every window for up to 1.5 s on a cold start. Running the finders in the database utility process would fix it, but Keychain reads must stay in a process whose prompt names Tamery (`architecture.md` → Device key), so `unlock` stays in main.
- **Attach the SSH host-key dialog to the window that asked.** With no focused window it opens app-modal, which pauses main's event loop until it is answered.
- **Record a trace from the Help menu.** Diagnosing a freeze took a shell script that relaunches the app with Chromium's startup tracing. A Help → Record performance trace item on Electron's `contentTracing` would let anyone send one.

## Developer experience

- **Enforce the 300-line ceiling in lint.** `code-style.md` sets it, but `oxlint.config.ts` has no `max-lines`, and about 40 files are over it (`definitions/sections/constraints.tsx` is 660). Split those files, then turn `max-lines` on so the ceiling holds without a review.
- **Name the missing AI key in dev.** `OPENROUTER_API_KEY` and `MISTRAL_API_KEY` are dev-optional in `apps/api/env.ts`, so a worktree whose `.env` predates them boots fine and every AI call answers an opaque `INTERNAL_SERVER_ERROR`. A startup warning listing the unset AI keys would point straight at the `.env`.
- **Close the kit sidebar's gaps.** Navigator call sites still restyle `@tamery/ui` sidebar parts: five pass `text-muted-foreground` to a `SidebarMenuButton` icon, `schema-row.tsx` turns `SidebarGroupLabel` into a hoverable row, and two use `size-3.5!` against the button's `[&_svg]:size-4`. A muted-icon default, an interactive group-label variant and a small trailing-icon size would move those into the kit (`tamery-ui` rule 11). Its `variant` is a `variant === 'muted' &&` switch inside `sidebar.tsx`; with those additions it becomes a `cva` in `sidebar.utils.ts` like every other kit variant.
- **Unpin `@shadcn/lint`.** 0.2.1 sees through wrapper components and flags about 40 call sites that restyle a kit part through `AppContextMenu` (it forwards `className` to `ContextMenuTrigger`), `SidebarGroupLabel`, `SidebarMenuButton` and `Item`, mostly in the visualizer inspector, table header cells and the navigator. The plugin is pinned to 0.2.0 until those move into kit variants or plain wrappers.
- **Check the oldest supported engine versions automatically.** Nothing runs the app's catalog, row and DDL queries against real servers, so a statement a 5-year-old engine lacks (ClickHouse 21.12's missing `format()` and Map `JSONExtract`, its plain-text mid-stream errors) ships unnoticed. A manual job that starts the oldest supported image of each engine in Docker (Postgres 14, MySQL 8.0, MariaDB 10.6, SQL Server 2022, ClickHouse 21.12, Oracle 21c, TimescaleDB 2.5) and runs every `createQuery` plus the runner's transaction, session and cancel calls would catch it before release.
- **Move every query into `@tamery/connection/queries`.** The app's catalog, row and DDL queries live in `apps/app/src/core/queries`, so the CLI, the proxy or an MCP server can only run raw SQL (`tamery query`) and `selectPage` is the one builder they share. Each file is already a per-dialect builder map plus a result `type`, tied to the app only by `createQuery`. Move those maps into the package with a thin runner over the `dialects/*` executors, and keep the app's `createQuery` as the wrapper that adds IPC or the proxy, the query log, reconnect retries, toasts and collections.
- **A kit empty state with an icon.** `PaneEmpty` (`apps/app/src/components/pane-empty.tsx`) and the share site's `EmptyState` are the same `Empty` composite (muted icon, title, description, optional action), and the site's deep-link status builds it by hand again; one `packages/ui` custom component would serve all three.
- **A kit switch field.** An `OptionField` holding a `Switch` bound to a form field is written out in the share form, three times in `column-dialog.tsx` and in `drop-dialog.tsx`; a `field.Switch` on the kit's form hook would save about eight lines a use.
- **Keep `todesktop.json` formatted on install.** `scripts/sync-pnpm-versions.ts` rewrites it with `JSON.stringify`, which expands the one-line arrays oxfmt keeps inline, so every pnpm bump leaves formatting churn until `pnpm fix` runs. Writing only the `pnpmVersion` line (as it already does for the workflow YAML) would avoid it.
- **Serialize `@tamery/mongo/shell` through the BSON library once callers hold instances.** `toShell` is hand-rolled because its input is relaxed Extended JSON with 64-bit longs pre-wrapped as `{$numberLong}`, which no single `EJSON.deserialize` mode reproduces (`relaxed` drops Long precision, canonical re-wraps every `1` as `NumberInt`). `@mongodb-js/shell-bson-parser@2.0.0`'s `toJSString` (Bun-ESM-safe, unlike 1.6.3) would replace the whole file if the runtime handed it real BSON instances instead of wire JSON — then the `keepLongs`/`toWire` dance in `dialects/mongodb/run.ts` could go too.
- **Drop the `require` workaround for `@mongodb-js/shell-bson-parser`.** `dialects/mongodb/client.ts` loads it through `createRequire` because 1.6.3's ESM wrapper loses its exports under Bun; 2.0.0 ships real ESM that imports cleanly, so bumping the catalog would let it be a normal `import`.
- **Hoist the identical `statementAt`.** `@tamery/mongo/statements` and `@tamery/sql/statements` export a byte-identical `statementAt`; one copy in `@tamery/shared` would serve both.

- **Warn on a duplicate connection name.** A second connection with an existing name saves silently, and in the switcher the two rows differ only by their colour dot.

## Sharing

- **Values rendered by type on the share page.** Cells are plain text today apart from booleans; enums, dates and JSON could reuse the grid's renderers once they live outside `apps/app`.
- **Viewer filters.** Viewers can only sort and page; a search over the shown columns, narrowing on top of the owner's filters, would cover most "find my row" visits.

- **Share a saved query.** A share is one table; a share of a saved runner query would cover joins and aggregates, with the same read-only and public-host checks.
- **Say why Share is greyed out when the share list fails.** The ⋯ menu's **Share** waits for the share list, so offline or with the API down it stays disabled with no reason; a muted trailing "Offline" like "Needs Full sync" would explain it.
- **Show free links left in the share dialog.** A Free user learns about the 3-link limit only when **Share** opens the upgrade dialog; a muted "2 of 3 free links" footnote on New link would set the expectation first.
- **Renew an expired link from the dialog.** An expired link still opens in the dialog on its old date; picking a new expiry works, but the dialog never says the link is already dead for viewers.
- **Keep the share page's header when the first rows fail.** A failure on the first page shows the full-page status; keeping the title, filters and column headers with an inline Try again in the grid would say less loudly that only the rows are missing.
- **Horizontal-only scroll for the grid's cell scroll.** Home/End on a read-only grid's header row scrolls back to the top when the target column is not mounted, since the shared scroll-to-cell always scrolls both axes.
- **Count the free share limit when an expired link is renewed.** Only creating a link checks the limit, so giving an expired link a new date or no expiry can leave a Free user with more than 3 live links.

## Security

- **Keep the API session token out of plain localStorage on desktop.** Chromium stores localStorage unencrypted on disk, and the token resolves every Full-sync connection string through `connections.resolve`; wrapping it with `safeStorage` in main, like the device key, would close that. The MCP token in `mcp.json` has the same gap.
- **Run agent reads on Postgres over the extended protocol.** It refuses a second statement outright, so a future tokenizer mismatch could not reach past the read-only transaction.
- **Show a short code on both sides of the sign-in handoff.** The browser now asks before signing an app in, but a matching code would stop a phished link from being confirmed blindly.
- **Limit which images AI answers load.** Markdown images load from any host, so a prompt-injected answer can send conversation text to a remote server in an image URL.
- **Authenticate the Railway alert webhook.** Anyone can post to it and send email to the alerts inbox; a secret in the webhook URL would do.
- **Pair the web app with `tamery proxy`.** The web app now ignores a local proxy that answers for another account, but a process that knows the user id can still claim the port; a secret the CLI shows once and the browser keeps would close it.
- **Cap open sessions and transactions per user on the cloud proxy.** Each holds a database socket for up to 15 idle minutes with no per-user limit, so one account can run the shared proxy out of file descriptors.
- **Longer share passwords.** The minimum is 4 characters against 1000 tries per 10 minutes per share, so a 4-digit PIN falls in under two hours and an attacker can spend the budget to lock real viewers out.
- **Rate-limit by the real client IP.** The API and proxy sit behind Cloudflare and key their limits on `x-real-ip`; if that is the edge's address, every user behind one edge shares the email-code and share-unlock budgets. `cf-connecting-ip` is the client.
- **Security headers on every host.** None of tamery.app, web, docs or the API send HSTS, `frame-ancestors` or `nosniff`, and the web app's CSP allows inline scripts with no `connect-src`.
- **Ask for a fresh sign-in before turning two-factor off.** `allowPasswordless` lets a stolen session disable TOTP or enroll its own.
- **End-to-end encrypt cloud connection strings.** The server decrypts them server-side (`getWorkspaceSecret` + `decryptConnectionString`), so full server access reads every stored string. Deriving the workspace key from a passphrase the server never receives — with cross-device key sync and a recovery story — would keep plaintext off the server entirely, at the cost of making `resolve`/`sync`/proxy pass ciphertext through and losing recovery when the passphrase is lost.
