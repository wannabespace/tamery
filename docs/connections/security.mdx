## Connection details

Connection strings are encrypted on your device. On desktop, the device key uses the system keychain where available.

You choose what reaches Tamery's cloud when you create a connection:

| Sync type | Stored in the cloud |
| --- | --- |
| **Full** | The complete connection string, encrypted. |
| **No password** | Connection details without the password, SSH secrets, SSL key secrets, access token, `Authorization` header, or MongoDB `authMechanismProperties`. When someone changes anything but the database, such as the server, user, SSH host or SSL settings, each device asks for the secrets again instead of sending them on. |
| **Metadata only** | Name, engine, label, and color. No connection string. |

Synced connection strings are encrypted with a workspace key. They are decrypted on Tamery's server when another device retrieves them, then sent over HTTPS. This is not end-to-end encryption.

## Where queries run

- **Desktop:** your computer connects to the database directly.
- **Web with [`tamery bridge`](/cli/overview):** the computer running the bridge connects to the database. Queries carry connection IDs, and the bridge gets each connection string through your account. Only the details your sync type keeps off Tamery's servers go from the browser to the bridge, once. Tamery's servers confirm that the bridge and the browser are signed in to the same account, and the bridge refuses requests that reach it through another address than its **Bridge URL**.
- **Web without a bridge:** Tamery's cloud proxy connects to public database servers and handles the query and its results.

The cloud proxy cannot reach private addresses, open SQLite, DuckDB and certificate files on your computer, or sign in to MongoDB with AWS, OIDC or Kerberos credentials. Use desktop or the bridge for those. The bridge skips files in app data folders and uses those credentials only for MongoDB Atlas, so a few of these need desktop. Connections whose secrets stay on your device also need desktop or the bridge.

### Cloud proxy IP addresses

If your database only accepts allowlisted IP addresses, add these so the cloud proxy can reach it:

```text
35.246.231.22
34.40.119.38
```

Add both. The proxy can connect from either one. Desktop and `tamery bridge` connect from your own network, so allow that address instead.

Only Tamery's cloud proxy uses these addresses, but it connects for every Tamery user. An allowlist narrows who can reach your database, and the database password still protects it.

Encryption between Tamery and your database depends on the connection's SSL settings. The cloud proxy never connects to PostgreSQL or MySQL unencrypted unless the string turns SSL off.

## SSH tunnels

SSH tunnels run on desktop and on the computer running `tamery bridge`. Tamery checks the server's host key and asks before trusting an unknown one, for the bridge in the web app. A changed key is refused.

You can use your SSH agent, a key file, a pasted private key, or a password. `~/.ssh/config` is supported; `ProxyJump` and `ProxyCommand` are not.

## What else we store

Saved queries and AI chats are stored on our servers, so they follow you to every device. They are kept per database and go away when you remove the connection.

Query history and the query logger stay on the device that ran the queries. So do your Navigator, tab, and table layout.

## AI and your data

AI requests go through our servers to external model providers. The chat sends your messages. Editor and filter features also send the schema context they need.

The built-in chat does not execute SQL. Coding agents connected through [MCP](/mcp/overview#connection-access) can read data and make changes according to the access you grant; their results become part of the agent's context.

### AI help with a failed test

**Explain with AI** sends connection diagnostics when you click it. Tamery removes connection identifiers and secrets from the error, and sends details such as the engine, port, SSL options, and whether the host is local or public.
