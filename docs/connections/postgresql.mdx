Click **New connection** and paste your provider's connection string, or fill in the fields:

```text
postgresql://user:password@localhost:5432/mydb
```

Both `postgresql://` and `postgres://` work. The default port is **5432**.

Tamery signs in with the password saved in the connection only. It never reads `PGPASSWORD` or `~/.pgpass` when it connects, so a connection with no password sends none. To use a `.pgpass` entry, pick it from the databases found on this computer when you create the connection.

## Hosted databases

Copy the connection string from Supabase, Neon, Railway, or wherever your database lives. If it still says `[YOUR-PASSWORD]` or similar, Tamery clears the placeholder and asks for the real password.

Pooled addresses break transactions, so Tamery switches them to a session or direct address. Neon's `-pooler` host becomes the direct host, and Supabase's port 6543 becomes 5432. The form shows every change it made.

On Supabase, the direct server is IPv6 only. If your network has no IPv6, use the **Session pooler** string instead.

## SSL

Keep whatever SSL settings your provider gives you.

| Option | Behavior |
| --- | --- |
| `sslmode=disable` | No encryption. |
| `sslmode=require` | Encrypted, without verifying the certificate. |
| `sslmode=no-verify` | Same as `require`. |
| `sslmode=verify-full` | Encrypted, with certificate and hostname verification. |

```text
postgresql://user:password@db.example.com:5432/mydb?sslmode=verify-full
```

With no SSL option, Tamery tries an encrypted connection without certificate verification. It drops to an unencrypted one only if the server itself says it has no SSL.

## TimescaleDB

TimescaleDB is a Postgres extension, so connect to it as PostgreSQL: paste your Timescale Cloud connection string or fill in the fields. Hypertables and continuous aggregates show up in the Navigator as tables and views. TimescaleDB's internal schemas, where chunks live, stay hidden.

For localhost in the web app, run the [local proxy](/cli/commands#tamery-proxy).
