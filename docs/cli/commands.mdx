`tamery --help` (`-h`) lists the commands, and `--help` after a command, such as `tamery bridge --help`, shows its options and subcommands. `tamery --version` (`-v`) prints the version.

## tamery login

```bash
tamery login
```

Opens the browser to sign this computer in to your Tamery account, and prints the link too. The link expires after 5 minutes. Confirm only if the page shows the code the terminal printed.

If the computer is already signed in, it prints the account. To switch accounts, run `tamery logout` first. Signing in to a different account removes the secrets and paired browsers saved for the old one.

## tamery whoami

```bash
tamery whoami
```

Prints the account this computer is signed in to, or says it isn't signed in and exits with code 1.

## tamery bridge

```bash
tamery bridge
```

Lets the web app run your connections on this computer until you press **Ctrl+C**. If the computer isn't signed in yet, it signs in first, as `tamery login` does. [Tamery CLI](/cli/overview#run-the-bridge) walks through pairing.

It prints the account, the address it listens on and a link to connect a browser. When a browser clicks **Connect**, it asks you whether to allow it. It also reports requests it refused because of a wrong host or origin.

| Flag | Use |
| --- | --- |
| `--port <port>` | Listen on another port. The default is `26380`. |
| `--public-url <url>` | The HTTPS address a tunnel or reverse proxy on this computer serves the bridge at. See [Reach a bridge on another computer](/cli/remote). |

If the port is taken, usually by another bridge, it says so and exits. Stop the other one or pass `--port`.

## tamery bridge approve

```bash
tamery bridge approve
```

Answers for a bridge that runs without a terminal to ask in, such as a service, a container or a detached session. When `tamery bridge` runs in a terminal you can see, the question appears there instead.

1. Keep the bridge running.
2. On the same computer, run `tamery bridge approve`. It waits for a browser.
3. In the web app, click **Connect** in **Settings → Bridge**.
4. Answer the question in the `approve` terminal.

The order of steps 2 and 3 doesn't matter, as long as you answer within 2 minutes of clicking **Connect**. At most 3 requests wait at a time; more are declined.

## tamery bridge unpair-all

```bash
tamery bridge unpair-all
```

Disconnects every paired browser, also from a bridge that is already running. Each one needs to be allowed again. Saved secrets stay.

## tamery update

```bash
tamery update
```

Installs the latest version the way you installed the CLI: with the install script, npm, pnpm or Bun. It shows that tool's output, then asks you to restart `tamery bridge` if it is running. When you already have the latest version, it says so and installs nothing. On a release candidate, it also installs a newer release candidate. It ignores `TAMERY_VERSION`: to install a specific version, run the install script with it.

If the update fails, for example because npm needs permissions you don't have, it says why. Fix that and run `tamery update` again. On Windows, a `tamery bridge` that is still running can hold the file the update replaces: stop it and try again.

If you installed with the script but run `tamery` from another folder, the update goes to `~/.tamery/bin` and the command says so. Delete the other copy, or replace it with the new one.

## tamery logout

```bash
tamery logout
```

Signs the CLI out of your account and deletes what it stored on this computer: the session, the saved secrets, their key in the keychain, and every pairing. The next `tamery bridge` signs in again, so this is also how you switch accounts.
