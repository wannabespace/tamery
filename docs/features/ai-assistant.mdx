Open a connection and press **Cmd+L** (**Ctrl+L**), or pick **New chat** from the **+** menu in the tab bar. The chat opens in its own tab, next to your tables and queries. Ask about your data in plain words.

Try:

- “Which customers ordered the most last month?”
- “Why does this SQL fail?”
- “Set the status of order 1042 to shipped.”

Each database keeps its own chats, on all your devices. Every chat is a tab you can switch to, close and reopen; a new one takes its title from your first question. **New chat** goes back to an open chat you have not written in yet instead of opening another; text you typed but did not send stays in its chat as a draft, listed under **Chats** until you send or clear it. You can stop an answer halfway, and an answer still being written survives a window reload.

To show the agent something, attach up to four images or PDFs of 5 MB each: click **+** under the message box, paste them, or drop them on it. To speak instead of typing, click the microphone, talk for up to two minutes, and click it again; what you said lands in the message box for you to check before sending. **Esc** drops a recording. The desktop app asks for microphone access the first time.

While the agent works you can keep typing: **Enter** queues your message, and it goes out as soon as the answer ends. **⌘ Enter**, or the **Send now** button, stops the agent and sends your message at once. Queued messages show above the message box, where the arrow sends one at once and **×** takes one back. In an empty message box, **Up arrow** brings back your last message.

Hover over a message of yours to copy or edit it; an edited message is asked again, and everything after it is replaced by the new answer. Under an answer you can copy it, ask again, and mark it as good or bad; it also says which model wrote it and how long it took. Click an attached image to see it whole; clicking a PDF saves it.

## What the agent does

A new chat opens with the message box in the middle and a few ways to start under it, such as an overview of the database or a data quality check; pick one to send it.

The agent reads your schema and runs read-only queries on its own. On a large database it searches table and column names and comments instead of listing everything, and before filtering on a value you named, it checks how that value is spelled in the column. It also looks through your saved queries and builds on them instead of starting from scratch. Each query shows as a card with the connection, its SQL and the rows it returned. From the card you can copy the SQL, open it in a new Query tab to change and rerun it, and, for a result with dates or categories and a number, show it as a chart. The agent reads at most 200 rows and about 60 KB per query, and a value longer than 2 KB reaches it cut short, so it filters and aggregates in SQL instead of reading whole tables.

The agent's reasoning and schema lookups between the parts of an answer fold into one line, such as **5 steps**; click it to see each step and what it found, such as **Read `orders` 12 columns**. Queries, changes waiting for you and notes always stay in view.

While it works, the chat names the step in progress, such as **Reading orders**. One message lets the agent take up to 25 steps. When it reaches that, the agent stops, says what it found and what is left, and **Continue** lets it carry on. **Continue** also appears when you stop the agent yourself.

Each month of Pro includes $5 of AI, which the chat shares with every other AI feature; past that, the chat spends [AI credits](/account/ai-credits), which you add by hand or top up automatically.

To change rows or the schema, the agent drafts the change instead of running it. Row edits and new rows appear as drafts in the table, schema changes as drafts in the [Schema visualizer](/features/schema-visualizer), and a deletion opens the table's delete confirmation. The chat shows each draft as a card that says what it changes, such as **Insert 1 row into orders**, with the rows it touches; **Open draft** takes you there, and nothing reaches the database until you save or apply it.

When a query is slow, the agent reads its plan and can draft the index that would help in the visualizer, for you to apply.

For anything a draft can't hold, the agent writes a statement instead. In **Ask** mode, the default, a statement that changes data or schema never runs on its own. The chat shows it with **Run** and **Decline**, and the agent continues once you choose. Statements that belong together come as one transaction, so you approve them once. The card waits for you when you reload or switch chats. On PostgreSQL and MySQL the card also says how many rows the database expects it to change. **Run** turns red when the statement removes data.

In **Auto** mode, picked under the message box, a statement that only adds, new rows or new tables and indexes, runs on its own when a check against your last message is sure it does only what you asked. Anything that changes or removes existing data, and anything the check is unsure of, still waits for **Run**. **Run** and **Decline** work while the check runs.

### Models

The menu under the message box picks the model that answers. It starts on **Auto**: for each message, Tamery weighs how hard the question is and answers with Claude Haiku, Sonnet or Opus, so a quick lookup costs less of your budget and a hard analysis still gets the strongest model. Within one chat, Auto never drops to a lighter model, so a long conversation stays consistent. Auto has no options of its own; pick a model to set them.

Below **Auto**, the models are grouped by company. The list shows the main models of Anthropic, OpenAI, Google and xAI; type to search all of them, including the rest from Google and Anthropic, DeepSeek, Moonshot, Qwen, Z.ai and Mistral. The models you picked lately sit under **Recent**; the cross next to one removes it from there. **Right arrow** on a model, or the arrow at the end of its row, opens its options; **Left arrow** or **Esc** goes back:

- **Effort**, from **Low** to **Max**: how hard the model thinks before answering. More effort is slower and spends more of your budget.
- **Context**: how much of the chat the model reads. **200K** keeps each answer cheaper and faster; the full window lets a chat run longer before it is summarized.
- **Fast**: sends the model to its fastest providers, which can cost more.

Each model keeps its own options, and both the pick and the options apply to every chat on this device. When a model's provider fails, the agent answers with another model from the list.

### Long chats

The circle next to the model shows how full the chat's context is. Click it to see the tokens, what the chat has cost so far, and **Compact now**. When a chat fills 80% of the window, its earlier messages are summarized before your next one is answered, so the agent keeps the facts and SQL it found without rereading the whole chat. A line in the chat marks where the summary ends, and your newest exchange always stays whole. **/compact** summarizes on demand.

### Subagents

For work that splits into independent pieces, such as checking several tables or connections, the agent can start subagents: separate agents with the same tools, each given one task. Up to four run side by side, and each reports back to the agent that started it. A subagent cannot start subagents of its own, and its changes wait for your **Run** like any other.

Each subagent shows as a line in the answer and in the **Subagents** row above the message box, with whether it is working, needs your approval, or is done. Open one to read its work and approve its changes:

- **Cmd+]** (**Ctrl+]**) shows the next subagent and **Cmd+[** (**Ctrl+[**) the previous one; past the last you are back in the chat.
- In the **Subagents** row, **Left arrow** and **Right arrow** move between them and **Enter** opens one.
- **Esc** goes back to the chat.

You read a subagent's chat but never write to it: it answers the agent, not you. Subagents do not appear in your list of chats.

### In the app

Ask the agent to open things for you: a table with filters and a sort ("show me last week's refunded orders"), SQL in a new Query tab, a download of a result as CSV or JSON, or the share dialog for a table. The share dialog opens filled in, and nothing is shared until you save it.

A table named in an answer opens when you click it. When a picture helps, such as how tables link, the agent draws a diagram.

To ask about one row, right-click it in a table and choose **Ask AI About Row**: a new chat opens with the row in the message box, ready for your question.

## Your chats

Pick **Chats** from the menu at the top of the [Navigator](/features/navigator), or press **Cmd+3** (**Ctrl+3**), to list every chat of the connection, grouped by date with pinned chats on top. Search finds a chat by its title or by anything said in it; click one to open it in a tab. The end of a chat's row shows how it stands: a spinner while the agent answers, a yellow dot when a change or note waits for you, a blue dot for an answer you have not opened yet, and a red dot when the answer failed. Right-click a chat, or use its **⋯** button, to rename, pin or delete it; renaming a chat's tab (double-click it, or **Rename** in its menu) renames the chat too. Deleting a chat can't be undone; a draft has only its delete button, and goes without asking.

## Schema notes

Notes tell the AI what your schema doesn't: "amounts are in cents", "status 3 means refunded", "use `orders_v2`, not `orders`". A note can be about the whole database, a table or one column. Every AI feature that works with that database reads them: the chat, **Ask AI** filters, and the Query editor's completions, edits and fixes.

When the agent learns something like this, it proposes a note. Edit the text if you like, then **Save** or **Dismiss**; nothing is kept until you save it. To add, edit or delete notes yourself, click a table in the [Schema visualizer](/features/schema-visualizer) and use **Notes** in its panel.

Notes sync to your other devices with the connection and are stored encrypted.

## Mentions and commands

Type **@** in the message box to mention:

| Mention | What the agent gets |
| --- | --- |
| A table of this connection | Its columns, keys, and indexes, so it can write SQL right away |
| Another connection | Access to it in this chat, for example to compare data across two databases |

Each connection is one row, standing for the database you opened in it most recently; **Enter** mentions that one. When a connection has more databases, **Right arrow** (or the arrow at the row's end) lists them, and **Left arrow** or **Esc** goes back. Typing a database's name finds it directly.

The agent queries each connection on its own, then joins or compares the results with SQL in the chat itself, so matching rows across databases is exact rather than done by eye. The joined table shows as a **Combined results** card.

Type **/** at the start of a message for commands. Picking one writes it in the message box, and **Enter** runs it:

| Command             | What it does                      |
| ------------------- | --------------------------------- |
| **/new**            | Starts a new chat                 |
| **/model**          | Opens the model and effort picker |
| **/retry**          | Asks your last message again      |
| **/copy**           | Copies the last answer            |
| **/compact**        | Summarizes the chat so far        |
| **/auto**, **/ask** | Switches how changes get approved |

On desktop, and in the web app with a [bridge](/cli/overview), the same menu lists your own agent skills and commands, read from `~/.claude/skills`, `~/.claude/commands`, `~/.agents/skills` and `~/.codex/skills`, each as **/skill:** and its name, so a skill never looks like one of the commands above. Picking one sends its instructions with your message; they never let a change skip **Run**. A file over 32 KB is left out.

Chats are stored on our servers and processed by external AI providers. See [Security and privacy](/connections/security#ai-and-your-data).

## AI elsewhere in Tamery

In the table browser, describe the rows you want and choose [**Ask AI**](/features/table-browser#find-the-rows-you-need).

In the Query editor, [**Edit with AI**, **Fix with AI**, and completions](/features/query-editor#get-ai-help) see your schema without you pasting it.

When a connection test fails, **Explain with AI** tells you what probably went wrong.

The chat and SQL help need [Pro](/account/plans). On Free you get 20 AI filters a week, and **Explain with AI** is free for everyone. Tamery picks the model for each task, so there is nothing to configure.

To let a coding agent look at your tables and run SQL itself, connect it through [MCP](/mcp/overview).
